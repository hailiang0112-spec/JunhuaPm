## 决策记录
- 链路入口｜背景：用户要求「把 PRD 往下继续」｜结论：按 PRD Master 门禁，先补《解题方案书》，逆向 PRD 作为输入材料｜来源：AI（依据 prd-master 接管门禁）
- 解题方向｜背景：四类扯皮（增项、质量、工期、图纸与现场不一致）｜结论：先解「图纸与现场一致」；路线 A 规则+证据链；放行关口+条件提醒；主指标=覆盖前发现比例；水电阶段验证；检查经验库由质检审核；最小切口从砌墙开始｜来源：用户

- PRD 范围｜背景：阶段 1 访谈｜结论：多工地、装修公司运营；原型全部功能+证据链；手机电脑自适应网页；系统内签认只追加留痕；付款只提示；经验库公司级；邀请制+手机号密码；网页待办+复制微信消息；公司负责公有云；业主可委托代理人放行，超时只提醒（D-1~D-12）｜来源：用户
- 设计期需求修订 rev2｜背景：设计中发现代理人进不来、驳回后路径、新增检查点等缺口｜结论：D-13~D-17（业主方成员、驳回可重提、新增检查点直接生效、异地备份、8 条小规则）；requirements.md rev2，change-impact.md｜来源：用户
- 设计方向｜结论：首屏我的待办；电脑左侧导航+手机底部4标签；沿用原型浅色风格+印章式状态标签；React+antd / Django+DRF / PostgreSQL / Docker 单机；pdf 服务端渲染成图（兼容 iOS 16）｜来源：用户（风格）/AI（技术选型）

- rev2 设计同步｜背景：用户 2026-10-27 拍板 RA-016~024｜结论：已签认/待重签基线新增检查点直接生效、留痕、知会业主，原 DEC-210「并入重签稿」作废；待签认期间基线（含新增检查点）锁定，需业主退回；驳回变更单可修改后重新提交（编号不变、回待定价、留驳回历史）；新增业主方成员角色、公司管理员项目内只读；临时密码一次性显示不落日志；本地存储模式须异地备份；HTTPS 用云厂商免费证书｜来源：用户
- 知会待办消失方式｜背景：AC-F06-16 未规定知会待办何时消失｜结论：DEC-118「知道了」由本人确认后移除（DATA-F16-01 todo_ack）｜来源：AI（待用户复核）
- 状态文案｜背景：TDD 校验器把「待定」识别为占位词｜结论：变更单状态「待定价」全局改为「待预算定价」，ID/revision 不变｜来源：AI

- 前端不用 antd｜背景：原型已有完整设计系统 CSS（tokens.css、app.css）｜结论：前端直接复用原型 CSS 与自写轻组件（Seal、ConfirmDialog 等），不引入组件库，视觉与原型一致、包更小；技术方案需同步｜来源：AI（交付时向用户汇报）
- 并行开发约定｜结论：共享文件（models、perms、urls、base、services、Shell、ui、api、session、routes）由负责人统一维护，各代理只改自己的模块文件，按 app/DEV_GUIDE.md 跨模块接口对接｜来源：AI
- 异地备份目标｜背景：镜像构建离线、无 rsync/ssh｜结论：异地目标实现为 dir（公司另一台服务器/NAS 挂载目录）与 s3（另一存储桶）两种，替代原 ssh+rsync；同步后逐个比对本次上传对象 SHA-256｜来源：AI（交付时汇报）

- 后台任务范围｜结论：worker 只处理证据包导出（临时文件 + 流式下载）；生产 JOBS_INLINE=0，开发与测试内联｜来源：AI（技术方案 §9）
- 模板检查点｜结论：建项目时深拷贝为工作项的 checkpoint_hints，新建检查点一键填入（检查点必须钉在签认图纸上）｜来源：AI
- 图纸分册入口｜结论：保留设计经理「新建分册」次要按钮，否则新项目无法上传首张图纸｜来源：AI（与页面规格不同，交付时汇报）
- 试用访问｜背景：云容器不接受入站连接｜结论：试用版以截图交付，用户可在自有机器 docker compose 启动或要求推送 GitHub｜来源：AI
- E2E 上传文件方式｜背景：SMOKE-02 中 Playwright 1.63 对含中文的本地路径 setInputFiles 得到 0 个文件，表现像「请上传 PDF 或图片版图纸」｜结论：E2E 脚本一律以 {name, mimeType, buffer} 传文件（保留中文文件名），不是产品缺陷；SMOKE-02 脚本 output/tests/e2e/smoke02.js 已通过｜来源：AI

- 待重签待办｜背景：浏览器 E2E 发现新版签认后无「待重签」待办｜结论：新增待办类型「基线待重签」（项目经理与业主），AC-F04-07｜来源：AI
- 停用房间后计划导回｜结论：已有工作项可沿用停用楼层/房间原位置，新工作项仍不能放入停用房间｜来源：AI

- RULE-04 暂缓｜背景：本环境无 iOS Safari 16 / 安卓微信真机与云真机账号｜结论：用户决定暂缓 RULE-04，按有条件交付；台账如实保持 pending，砌墙试运行首周真机补测后回填｜来源：用户（2026-10-27「确认暂缓 RULE-04」）
