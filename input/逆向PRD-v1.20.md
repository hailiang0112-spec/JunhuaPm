## 1. 产品概述

### 1.1 背景
自住别墅精装工程周期长（近一年）、工种多（6 大工段）、空间多（6 层 32 个房间），业主、施工方、设计、监理之间的信息靠口头和微信，进度、质量问题、变更约定难以追溯。

### 1.2 产品定位
面向单个装修项目的**全周期进度 / 质量 / 问题闭环**管理工具，以「**阶段 × 楼层 × 房间**」三级定位组织全部工作事项，所有指标与图表从基础数据自动推导。

### 1.3 示例项目信息（内置演示数据）
| 字段 | 值 |
|---|---|
| 项目名称 | 君华新城 · 联排别墅装修工程 |
| 概况 | 业主自住精装 · 建面 386㎡ · 负一楼 / 夹层 / 一至三楼 / 楼顶阳台 |
| 施工总包 | 君华建装（项目经理 张工） |
| 业主代表 | 刘先生 |
| 设计单位 | 尚庭设计（李工） |
| 监理 | 中正监理（王工） |
| 项目周期 | 2026-09-19 ~ 2027-08-30（346 天，含首尾） |

### 1.4 目标用户与角色
| 角色 | 主要诉求 | 典型操作 |
|---|---|---|
| 业主 | 掌握整体进度、问题是否解决、约定是否兑现 | 看总览、看房间进度、公告栏留言、查合同资料 |
| 工地经理 / 项目经理 | 排计划、记出勤、登记与闭环问题 | 编辑阶段与事项、登记出勤、上传验收图片、导入计划 |
| 设计师 | 跟踪设计变更与现场偏差 | 处理问题、补充事项、上传图纸与效果图、留言 |
| 监理 | 验收与质量把控 | 查验收标准、登记问题、跟踪闭环 |

> 注：当前版本无账号体系，角色仅体现在公告栏的「留言板块」区分上。

### 1.5 产品目标与成功指标
- 进度透明：任意时刻可见 **实际完成度 vs 计划基准** 的偏差（pp）。
- 问题闭环：闭环率目标 **≥ 80%**，超期问题自动预警。
- 可追溯：计划类变更 100% 自动留档，只追加不可覆盖。
- 资料集中：图纸、效果图、合同、完工照片统一归档。

## 3. 核心业务模型

### 3.1 维度定义

**施工阶段（6 个，固定，可改名不可增删）**

| ID | 名称 | 计划起止 | 权重 | 班组 | 施工范围 | 内置事项数 |
|---|---|---|---|---|---|---|
| p1 | 砌墙 | 09-19 ~ 10-18 | 8% | 瓦工班 · 陈师傅（4人） | 新砌隔墙、构造柱、门窗过梁、斜砌塞缝挂网 | 31 |
| p2 | 水电 | 10-19 ~ 01-18 | 22% | 水电班 · 赵师傅（6人） | 强弱电布管穿线、给排水、中央空调新风、打压试水与隐蔽验收 | 36 |
| p3 | 铺砖 | 12-19 ~ 03-18 | 18% | 铺砖班 · 周师傅（7人） | 防水闭水、墙地砖铺贴、石材、勾缝与成品保护 | 33 |
| p4 | 木工 | 02-19 ~ 06-18 | 22% | 木工班 · 吴师傅（8人） | 吊顶龙骨石膏板、柜体、木饰面、门套基层 | 30 |
| p5 | 油灰工 | 05-19 ~ 08-02 | 16% | 油灰班 · 郑师傅（5人） | 接缝防裂、阴阳角、腻子打磨、底漆面漆、艺术漆 | 21 |
| p6 | 安装收尾 | 07-19 ~ 08-30 | 14% | 安装班（计划 8 人） | 灯具面板、洁具五金、橱柜、木门地板、风口、光伏、保洁竣工 | 36 |

合计 **187 项**工作事项；阶段允许时间重叠（工序穿插）。

**楼层（6 + 1）**：负一楼(B1) / 夹层 / 一楼(1F) / 二楼(2F) / 三楼(3F) / 楼顶阳台(RF)，外加「全楼通用」（材料进场、系统调试、隐蔽验收、竣工验收等跨楼层通项）。每层有固定主题色。

**房间（32 个）**

| 楼层 | 房间 / 区域 |
|---|---|
| 负一楼（5） | 车库、衣帽间、保姆间、负一楼卫生间、负一层大厅 |
| 夹层（4） | 电梯间、储藏室 1、储藏室 2、设备间 |
| 一楼（6） | 厨房、餐厅、电梯间、客厅、读书区、佛堂 |
| 二楼（7） | 电梯间、书房 A、卧室 A、卫生间 A、书房 B、卧室 B、卫生间 B |
| 三楼（6） | 电梯间、主卧室、主衣帽间、主卫、多功能室、多功能室洗手间 |
| 楼顶（4） | 洗衣间、楼顶阳台、种菜区、屋顶光伏 |

房间归属规则：楼层=全楼通用 → 房间强制为「全楼通用」；房间为空 → 「本层通用」；房间必须属于所选楼层。

### 3.2 实体与字段

**阶段 Phase**
| 字段 | 说明 | 规则 |
|---|---|---|
| id / name / icon / color | 标识与展示 | name 可改名 |
| start / end | 计划开始 / 结束 | 必填，start ≤ end |
| crew | 施工班组 / 负责人 | 文本 |
| w | 阶段权重 | 1–60%（表单）/ 1–100（导入），用于总览加权 |
| scope | 施工范围 | 文本 |
| status | 状态 | **自动推导**：进度 0 → 未开始；0~99.95 → 进行中；≥99.95 → 已完成 |

**工作事项 Task**
| 字段 | 说明 | 规则 |
|---|---|---|
| n | 事项名称 | 必填 |
| note | 工作说明（工艺做法 / 材料要求） | 选填；为空时由工序说明库自动补齐 |
| std | 验收标准（可量化判定） | 选填；同上 |
| fl / rm | 所属楼层 / 房间 | 级联选择，需匹配 |
| plan / act | 计划完成 / 实际完成日期 | 可只存 MM-DD，按所属阶段年份补全；act > plan 标「滞后」 |
| owner | 负责人 | 为空默认「待指派」 |
| w | 权重 | 1–5 整数 |
| pct | 完成度 | 0–100 整数，快捷 0/25/50/75/100 |
| files | 完工资料 | 文件 ID 列表 |

**问题 Issue**
| 字段 | 说明 | 规则 |
|---|---|---|
| id | 编号 | 内置 I01…；新增 `N` + 时间戳后 6 位 |
| pid | 所属阶段 | 必选 |
| t | 问题描述 | 必填 |
| d | 发现日期 | 默认今天 |
| lv | 等级 | 一般 / 重要 / 严重 |
| fl / rm | 楼层 / 房间 | 同事项规则 |
| fix | 对策方法 | 为空默认「待补充对策」 |
| owner | 对策负责人 | 为空默认「待指派」 |
| due | 要求闭环日期 | 默认今天 + 7 天 |
| st | 状态 | 未闭环 / 处理中 / 已闭环 |
| closed | 实际闭环日期 | 置为已闭环时记录当天 |

派生：超期天数 = max(0, 今天 − due)（未闭环时）；闭环耗时 = closed − d；挂起天数 = 今天 − d。

**每日出勤 Attendance**：按阶段 × 日期记录人数（0–40）。系统按阶段工期生成基线（周日休息、今天之后为 0），人工登记覆盖基线并标记「手工登记」。

**验收图片 Photo**：cap 标题、st 状态（施工中 / 待复验 / 已验收，循环切换）、src（压缩后 Base64）、date。

**计划变更留档 ChangeLog**：t 时间、pid/pname、note 原因（≤120 字）、items[ {f 字段, from, to, dd 工期增减天数} ]。

**文件 File**：id、sec 所属专区（ld/r3/ct/task/extra）、fo 文件夹或归属引用、name、type、size、ts、w/h。

**文件夹 Folder**：按专区 {id, name}。

**补充事项 Extra**：id、title、desc、date 提出日期、due 约定完成日期、owner 责任人、st（待处理 / 处理中 / 已完成）、files。

**留言 Notice**：id、board（owner / manager / designer）、who、text、ts、re（回复的父留言 ID）。

### 3.3 核心计算口径
| 指标 | 公式 |
|---|---|
| 阶段完成度 | Σ(事项权重 × 完成度) ÷ Σ事项权重 |
| 阶段计划基准 | (今天 − start) ÷ (end − start)，限定 0–100% |
| 总体完成度 | Σ(阶段权重 × 阶段完成度) ÷ Σ阶段权重 |
| 总体计划基准 | Σ(阶段权重 × 阶段计划基准) ÷ Σ阶段权重 |
| 进度偏差 | 总体完成度 − 计划基准（pp，≥0 领先 / <0 滞后） |
| 项目周期 | 各阶段最早 start ~ 最晚 end（无阶段时兜底常量） |
| 总工期 | 周期天数 **含首尾**（+1） |
| 已用天数 | 开工日至今天，含首尾，限定在 [0, 总工期] |
| 工期进度 | 已用 ÷ 总工期 |
| 闭环率 | 已闭环数 ÷ 问题总数（无问题时 100%） |
| 问题遗留 | 处理中 + 未闭环 |
| 累计人工日 | 全部阶段每日出勤人数之和 |
| 楼层 / 房间完成度 | 归属该楼层 / 房间的事项按权重加权 |

## 4. 功能需求

### 4.1 全局框架（F-00）
- **左侧导航**：每项显示图标、名称、状态徽标、进度条与百分比；档案专区显示文件数 / 条数及子类提示。
- **侧栏底部摘要**：项目周期、计划工期、已用/总天数、累计人工日、楼层/房间数、工作事项数及覆盖房间数、计划变更条数、档案文件数与存储模式、保存状态。
- **顶栏**：页面标题 + 副标题（项目名 + 范围），全局操作按钮。
- **交互基础**：弹窗（遮罩点击/ESC 关闭）、图片灯箱、Toast 提示。
- **今天的取值**：默认本机日期；支持 `window.__FIX_TODAY__` 固定演示日。

### 4.2 项目总览（F-01）
| 模块 | 内容 | 交互 |
|---|---|---|
| KPI 六卡 | 总体完成度（含计划对比与偏差）、工期进度（已用/剩余）、今日出勤（在施阶段数、累计人工日）、发现问题（超期未闭环数）、已闭环（闭环率 vs 目标 80%）、问题遗留（处理中/未闭环） | — |
| 六阶段甘特图 | 计划 vs 实际对比时间轴 | 「查看明细」弹出阶段进度明细表（计划起止、工期、计划变更偏移如 (+3d)、实际进度、计划基准、偏差、人工日、问题/闭环） |
| 楼层 × 阶段矩阵 | 热力图，7 档色阶（0%、1–39、40–69、70–89、90–99、100%、无事项） | 点行名看楼层全部事项；点单元格进入对应阶段并筛选楼层 |
| 房间短板 TOP 8 | 完成度最低的 8 个房间（事项数、加权完成度、问题数） | 点击下钻房间详情 |
| 房间问题聚焦 TOP 6 | 问题数最多的 6 个房间（问题/闭环/遗留/闭环率） | 点击下钻 |
| 每日出勤日历 | 按月展示每日出勤总人数，5 级色阶（0 / 1–4 / 5–8 / 9–12 / 13+，周日休息单独标识），月度合计/天数/峰值 | 切换月份；「今日明细」看当日各阶段出勤 |
| 问题发现与闭环（按阶段） | 分组柱图：已闭环 / 处理中 / 未闭环 | 点柱下钻 |
| 问题遗留清单 | 未闭环问题按超期天数降序（编号、阶段、楼层、描述、等级、状态、负责人、要求闭环、超期） | 详情、一键闭环、登记问题 |
| 计划变更台账 | 最近 6 条留档 + 累计条数、涉及阶段数 | 查看全部、导出 CSV |
| 六阶段速览卡 | 状态、进度、工期、计划基准、累计出勤、峰值/施工天数、事项数、问题/闭环 | 点卡片进入阶段页 |

### 4.3 楼层 / 房间视图（F-02）
- **KPI 六卡**：楼层/房间数、事项覆盖（已完成、通用项数）、房间覆盖（已完工房间数）、进展最快房间、短板房间、问题集中房间（及遗留最多房间）。
- **楼层 × 阶段矩阵**、**房间 × 阶段矩阵**（32 行按楼层分组；点房间名看跨阶段全部事项，点单元格跳阶段并筛选该房间）。
- **各房间完成度卡片**：按楼层分组，条形 + 事项数，有遗留问题标红。
- **各楼层工作量分布**（按事项权重合计、按阶段堆叠）与**各楼层问题分布**（发现/闭环/遗留）。
- **房间问题分布表**、**楼层明细表**（房间数/事项/完成度/问题闭环），均可放大。
- **楼层·房间速览卡**：楼层状态、进度、房间/事项/问题/遗留数、房间 chip（含完成度，点击打开房间详情）。
- **楼层详情 / 房间详情弹窗**：按阶段分组列出事项（含说明、验收标准、资料按钮）；可「为该楼层/房间登记问题」（预填楼层房间）。

### 4.4 阶段详情（F-03，六阶段共用模板）
1. **操作条**：编辑阶段信息、＋新增工作事项、登记每日出勤、批量登记出勤、＋登记问题。
2. **KPI 六卡**：阶段进度（vs 计划基准）、计划/实际开始、计划/实际结束（完工或在施至某日）、工期/实际施工天数、出勤峰值/累计（手工登记天数）、事项完成数/问题闭环数。
3. **计划变更留档卡**：本阶段最近 4 条 + 调整计划日期入口。
4. **总体工作事项表**
   - 筛选：楼层 chips + 房间 chips，显示筛选范围加权完成度与阶段整体完成度。
   - 列：#、工作事项、工作说明（附「验收」标签块）、楼层/房间、计划、实际（滞后标红）、负责人、权重、完成度条、状态、资料（带数量徽标）、编辑/删除。
   - 窄屏（≤1200px）自动隐藏「工作说明」列。
   - 支持「放大查看」。
5. **楼层·房间分布（本阶段）**：按楼层与房间拆分本阶段工作内容与完成度，点击联动筛选事项表。
6. **每日出勤**：柱图 + 7 日移动平均线，周日休息底色；统计累计人工日、日均、峰值、施工天数。
7. **出勤明细台账**：逐日登记 / 还原（还原 = 删除人工覆盖回到基线）。
8. **验收图片**：卡片网格，状态标签（已验收/待复验/施工中计数），点击看大图，换状态、删除；上传后自动压缩（最长边 1280px、JPEG 0.72），默认状态「待复验」。
9. **发现问题与闭环管理**：筛选（全部/未闭环/处理中/已闭环）；问题卡显示编号、描述、等级、状态、楼层、超期天数、闭环耗时或挂起天数、发现日期（星期）、负责人、要求/实际闭环日期、对策；操作：编辑、标记闭环 / 重新打开、删除。

### 4.5 录入与编辑表单（F-04）

**编辑阶段信息**
- 字段：计划开始、计划结束、班组/负责人、阶段权重(%)、施工范围、本次变更原因（选填）。
- 标题栏内嵌工段下拉 + 正文「工段速览」chips，可在 6 个工段间切换（未保存的修改会丢失）。
- **保存后弹窗保持打开**，可连续修改全部工段；若切换过工段，后台页面同步跳转。
- 校验：起止必填、开始 ≤ 结束。
- 保存时逐字段比对，有变化才写留档（见 4.8）。
- 改日期后出勤基线与甘特图重算，已手工登记的出勤保留。

**新增 / 编辑工作事项**：字段见 3.2；编辑态可打开该事项资料面板；保存后阶段完成度 → 阶段状态 → 总览联动重算。删除事项时同步清理其资料文件（需确认）。

**登记出勤（单日）**：阶段（可切换）、日期（限本阶段工期内，显示星期）、人数 0–40；0 表示停工。
**批量登记出勤**：起止日期、每日人数、范围（区间每一天 / 仅工作日跳过周日 / 仅至今日）。

**登记 / 编辑问题**：字段见 3.2；从楼层/房间详情进入时预填；选「已闭环」记录今天为闭环日；改回其他状态清除闭环日。全局顶栏、总览、阶段页、楼层/房间详情均有入口。

**通用约定**：所有删除需二次确认；保存后 Toast 提示并全局重算。

### 4.6 工序说明库（F-05）
- 内置约 **71 条**工序规则（正则匹配事项名称 → [工作说明, 验收标准]），覆盖砌墙→水电→铺砖→木工→油灰→安装收尾。
- 按数组顺序匹配，首个命中生效，「先特异后通用」；同类工序在不同房间共用同一套说明。
- 事项自身已填写 note/std 时以数据为准，不被覆盖。
- 示例：「隔墙/砌筑」→ 240mm 加气块 + M5 砂浆…；验收：垂直度 ≤3mm、平整度 ≤3mm、灰缝 8–12mm、饱满度 ≥80%。

### 4.7 工作事项资料（F-06）
- 每个事项可上传多个图片 / 文件（完工照片、验收单），一次多选。
- 入口：阶段事项表、楼层详情、房间详情、事项编辑弹窗。
- 资料面板：缩略图网格，图片点击看大图，非图片点击下载，可删除。

### 4.8 计划变更留档（F-07）
| 项 | 规则 |
|---|---|
| 留档字段 | 计划开始、计划结束、负责人/班组、阶段权重、施工范围 |
| 触发 | 「保存并重算」时任一字段变化即追加 1 条；无变化不记录 |
| 内容 | 时间、阶段、变更项、变更前 → 变更后、工期增减天数（提前/延后）、原因备注 |
| 不可覆盖 | append-only，最新在前，上限 500 条，超出丢弃最旧 |
| 查看 | 阶段页卡片（最近 4 条）、总览台账（最近 6 条）、全部留档弹窗、阶段明细表「计划变更」列与偏移标记 |
| 累计偏移 | 相对内置基线计算计划工期延后/提前天数 |
| 导出 | CSV（记录时间, 阶段, 变更项, 变更前, 变更后, 工期影响(天), 变更原因备注）；JSON 备份包含 |
| 范围外 | 事项完成度、出勤、问题等业务数据不留档 |

### 4.9 房屋档案资料（F-08）

**平面布局图 / 三维效果图 / 装修合同（文件夹式）**
| 专区 | 默认分类 | 允许格式 |
|---|---|---|
| 平面布局图 | 负一层、夹层、一楼、二楼、三楼、屋顶阳台 | 图片、PDF |
| 三维效果图 | 同上 | 图片 |
| 装修合同 | 主合同、补充协议、报价与变更、付款凭证 | PDF、Word、Excel、图片 |

- 分类总览 → 进入分类 → 上传 / 预览 / 下载 / 删除；另有「未分类」桶。
- 分类可新建（含快捷楼层名）、重命名、删除。
- 单文件上限 40MB；大于 1.2MB 的图片上传前预处理压缩。

**补充事项（条目台账）**
- KPI：总数、待跟进、已完成、附件数。
- 列表排序：未完成在前，再按提出日期倒序；卡片显示序号、标题、状态、说明、提出/约定完成日期、责任人、附件 chips。
- 操作：新增、编辑、切换状态（待处理 → 处理中 → 已完成 循环）、删除、上传/管理附件。
- 首次加载注入 3 条演示台账（如「三楼卫生间增加浴缸」），用户增删后不再注入。

**业主公告栏（三方留言）**
- 三个板块：业主留言 / 工地经理留言 / 设计师留言，Tab 显示条数。
- 发布：留言人称呼（记忆该板块最近使用的称呼）+ 内容（各板块有示例占位）。
- 留言按时间倒序；支持对单条留言回复（一级回复，按时间正序）；逐条删除、清空本板块。

### 4.10 项目资料录入 · Excel 批量导入（F-09）
四步向导：

1. **取得表格**：下载空白模板（.xlsx，含填写说明、取值表、6 个工段、每工段 1 行示例）或导出当前计划（含全部事项、说明、验收标准）。
2. **选择文件**：支持 .xlsx / .xlsm / .csv；**按表头文字识别列**，列顺序可调整。
3. **自动校验**：错误逐行列出（行号），通过后方可导入；错误/警告各最多显示 60 条。
4. **导入选项**：□ 一并重置过程记录；☑ 导入前自动导出 JSON 备份（默认勾选）。

**模板结构**
| 工作表 | 列 |
|---|---|
| 施工阶段 | 序号、阶段名称、计划开始日期、计划结束日期、施工班组/负责人、阶段权重(%)、施工范围说明 |
| 工作事项 | 序号、施工阶段、工作事项名称、工作说明、验收标准、所属楼层、所属房间/区域、计划完成日期、实际完成日期、负责人、权重(1-5)、完成度(%) |
| 补充事项 | 序号、事项标题、说明、提出日期、约定完成日期、责任人、状态 |
| 填写说明 / 取值表 | 说明与可选值 |

模板格式要求：数值列为真数字（可求和排序）；日期列预设文本格式（防转序列号）；长文本自动换行；数据表带自动筛选。

**校验规则**
- 阶段名称：匹配内置名称；不匹配时按**行序**对应内置工段（警告）并采用新名称；不支持增删阶段；重复报错。
- 事项「施工阶段」列：可填新名、原名或序号 1–6。
- 日期：可识别多种格式；只给月日时按项目年份补全；开始晚于结束报错；空起止沿用内置值。
- 阶段权重 1–100；事项权重、完成度范围校验；楼层、房间名称匹配且房间须属于楼层。
- 缺阶段表：沿用内置阶段字段，仅重建事项（警告）。

**导入语义**
| 重建 | 默认保留 | 勾选「重置过程记录」后清空 |
|---|---|---|
| 阶段名称/起止/班组/权重/范围、全部工作事项、补充事项 | 问题台账、每日出勤、计划变更留档、已上传资料文件、公告栏 | 问题台账（含内置）、人工出勤、验收图片、计划变更留档 |

- 已上传的事项资料按「阶段 + 事项名」（其次仅事项名）自动重新挂接。
- 导入完成后跳转到首个有事项的阶段，提示重建数量与重挂资料数。

### 4.11 数据录入与备份（F-10）
- **数据概览**：项目周期、阶段、事项、楼层、房间、出勤台账（手工登记天数）、问题（新增数）、留档、验收图片（上传数）、资料库（存储模式、各专区数量）、数据状态。
- **快捷录入**：登记问题、登记出勤、编辑阶段信息、新增事项。
- **备份与还原**：导出 JSON、导出变更留档 CSV、查看留档、导入 JSON、重试连接本机资料库、恢复演示数据。
- **恢复演示数据**：清空覆盖层与本机文件本体，回到内置模板（需确认）。

### 4.12 使用说明（F-11）
弹窗内置：导航结构、工期口径、Excel 录入步骤、可编辑对象与联动关系、楼层/房间维度说明、留档规则、数据存储说明。内容随数据动态生成（如阶段名、房间清单）。

## 5. 数据与存储设计

### 5.1 分层架构
```
内置基础数据（BASE_PHASES，只读模板） + 工序说明库
        +  覆盖层 OVERLAY（localStorage，增量）
        ──rebuild()──▶ 运行数据 PHASES
        ──▶ 统计层（kpi / floorStat / roomStat）
        ──▶ 图表层（内联 SVG）
        ──▶ 视图层（render）
```

### 5.2 覆盖层结构（localStorage 键 `jh_villa_pm_v11`）
| 键 | 含义 | 覆盖方式 |
|---|---|---|
| phase | 阶段字段 | 字段级覆盖 |
| tasks | 各阶段事项 | 存在即整段替换（快照式） |
| att | 人工出勤 {pid:{date:n}} | 单日覆盖 |
| issues | 新增问题 | 追加 |
| edit | 内置问题字段修正 | 字段级 |
| delIssues | 已删除内置问题 | 标记 |
| closed | 闭环覆盖 {id:date} | 标记 |
| photos | 验收图片 | 整段替换 |
| log | 计划变更留档 | append-only |
| files / folders | 资料元数据 / 分类 | — |
| extra / notice / noticeName | 补充事项 / 留言 / 称呼记忆 | — |
| base | 时间轴基线标识 | 用于迁移 |

### 5.3 文件存储
- 文件本体存 **IndexedDB**（库 `jh_villa_files`，store `blobs`）；元数据存覆盖层。
- IndexedDB 不可用时**降级为内存 + 轻量存储**（单文件 ≤1.2MB、总量约 5MB），侧栏与面板明示当前模式，可「重试连接」。
- JSON 备份**不含文件本体**，换机需重新上传（界面需明确提示）。

### 5.4 基线迁移
内置时间轴换代时（`BASE_TAG` 不一致），仅丢弃本机阶段 start/end 覆盖，其他数据保留，并一次性 Toast 提示。

### 5.5 容量与异常
- localStorage 写入失败时修改仍在本次会话生效，状态提示「容量超限，请导出备份」。
- 验收图片压缩后存 Base64，可能触发容量上限。

| 类别 | 要求 |
|---|---|
| 部署 | 单 HTML 文件，双击即用，无后端、无外部依赖（xlsx 读写自实现：ZIP + CRC32 + 原生解压） |

| 可靠性 | 导入前自动备份；删除二次确认；留档不可覆盖 |
| 可测试 | 解析校验为同步纯函数；支持固定「今天」 |
| 安全 | 用户输入展示前 HTML 转义 |

## 7. 关键业务流程

**问题闭环**：发现 → 登记（阶段/楼层/房间/等级/对策/负责人/要求闭环日）→ 处理中 → 标记闭环（记录闭环日、计算耗时）→ 可重新打开；超期自动进入遗留清单置顶。

**计划调整**：阶段页编辑 → 修改日期/班组/权重/范围 + 原因 → 保存 → 自动比对留档 → 甘特、周期、工期、计划基准、出勤基线重算 → 可连续切换工段修改。

**开工前初始化**：下载模板 → 填写阶段与事项 → 导入校验 → 勾选「重置过程记录」→ 确认导入 → 软件仅剩计划。

## 8. 当前版本限制与后续规划建议
| # | 限制 | 建议 |
|---|---|---|
| 1 | 纯本机存储，无法多人协作，三方留言实际只能在同一设备 | 引入云端存储与账号体系，按角色授权（业主只读+留言、经理编辑等） |
| 2 | 阶段固定 6 个，不支持增删 | 支持自定义工段模板 |
| 3 | 楼层/房间写死在代码 | 房型配置化，支持多项目 |
| 4 | 出勤为演示生成基线 + 人工覆盖，无按工种/人员记录 | 按班组实名打卡，关联人工成本 |
| 5 | JSON 备份不含文件本体 | 支持打包导出（ZIP 含附件）或云端同步 |
| 6 | 无消息通知（超期、留言回复） | 增加提醒（微信/短信/邮件） |
| 7 | 无成本 / 付款节点管理 | 增加预算、增项费用、付款进度模块，与合同、补充事项联动 |
| 8 | 验收图片与事项资料两套上传机制并存 | 统一为资料库，验收图片作为事项资料的一种 |
| 9 | 移动端体验有限（现场使用场景多） | 设计移动端现场拍照登记问题流程 |
