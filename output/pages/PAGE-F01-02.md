## 2. 页面概述

- **定位**：一个工地的「人和规则」都在这里：谁在项目里、担任什么角色、谁替业主放行、项目走到哪个状态、放行要在多少小时内完成。
- **存在理由**：开工前各方职责与权限要明确（US-F01-01）；业主不在现场时放行不能卡工期（US-F01-02）。
- **不做什么**：
  - 不改动成员已产生的任何历史记录：移除成员只断开访问（AC-F01-06）。
  - 不做超时自动放行：时限只用于提醒（AC-F06-13）。
  - 项目状态不能回退（DEC-109）。

## 3. 用户与场景

| 角色 | 本页可做的事 |
| :--- | :--- |
| 公司管理员 | 看完整手机号；生成 / 撤销邀请（含公司管理员角色）；编辑成员角色；移除成员；重置密码；修改放行时限（AC-F06-17）。这些是管理操作，不受「公司管理员对项目业务数据只读」影响（AC-F01-13） |
| 项目经理 | 生成 / 撤销本项目邀请（不能选公司管理员角色）；推进项目状态；修改放行时限（AC-F06-17） |
| 业主（可多名） | 指定、更换、撤销业主代理人；生成 / 撤销自己发出的邀请，角色只能是「业主方成员」（AC-F02-09） |
| 业主代理人、业主方成员、设计经理、质检、预算专员 | 只读：成员列表（手机号打码）、项目状态、放行时限、代理人（业主方成员只读，AC-F01-12；放行时限对其只读，AC-F06-17） |

无权限的按钮直接隐藏（蓝图 §3）；服务端同样按「项目 × 角色」校验（NFR-003）。

- **场景 A 项目经理邀请质检**：点「生成邀请」→ 填手机号 186 0211 2201、勾选「质检」→ 生成 → 复制链接发微信。
- **场景 B 公司管理员重置密码**：赵会计忘记密码 → 「重置密码」→ 确认摘要 → 得到临时密码并复制给赵会计。
- **场景 C 业主更换代理人**：刘先生把代理人从刘太太换成自聘监理 → 确认摘要提示原代理人权限立即撤销。
- **场景 D 交房**：项目经理把状态从「施工中」推进为「已交房」，必须填写实际交房日期。
- **场景 E 业主邀请自聘监理**：刘先生点「生成邀请」→ 角色只出现「业主方成员」→ 生成链接发给钱工 → 钱工加入后只读查看；刘先生可再把钱工指定为代理人（AC-F02-09、AC-F01-12）。

## 6. 交互流程

```
生成邀请 → 填手机号、角色 → 生成
   ├─ 项目经理选了公司管理员 → 「只有公司管理员可以设置该角色」（AC-F02-04）
   ├─ 业主打开 → 只能选业主方成员；服务端对其他角色返回「业主只能邀请业主方成员」（AC-F02-09）
   └─ 成功 → 链接（一次性，7 天）→ 复制 → 提示「已复制」→ 邀请记录新增「待使用」

撤销邀请 → 确认摘要（手机号、角色、生成时间）→ 印章变「已撤销」，该链接打开显示失效态（AC-F02-03）

编辑角色（公司管理员）→ 勾选 → 保存 → 提示「已更新 孙工 的角色」

移除成员（公司管理员）→ 确认摘要 → 移除
   摘要：成员、角色；「下一次请求起无法访问本项目」；「已有签认、核对、放行、变更、问题和留言保留原署名，内容不变」（AC-F01-06）
   若被移除者是代理人 → 摘要追加「其业主代理人身份同时撤销」

重置密码（公司管理员）→ 确认摘要 → 生成一次性临时密码，只在结果弹窗显示一次，可复制，关闭后不可再查看，不写入任何日志（NFR-006 rev2）
   → 该成员用临时密码登录后必须先改密码（AC-F02-07，PAGE-F02-03 承接）；重置动作记入操作日志，日志不含临时密码

推进项目状态（项目经理）
   筹备 → 施工中：确认摘要 → 保存并留痕
   施工中 → 已交房：必须填写实际交房日期，否则「请填写实际交房日期」并拒绝保存（AC-F01-11）→ 确认摘要 → 保存并留痕

放行时限（公司管理员、项目经理，AC-F06-17）→ 改为 1–72 的整数 → 保存 → 提示「放行时限已改为 36 小时」；其他角色看不到修改表单

业主代理人（业主）
   指定：选择成员 → 确认摘要 → 生效（AC-F01-07）
   更换：选择新成员 → 确认摘要「原代理人刘太太的放行权限将立即撤销」→ 新成员成为唯一代理人，留痕（AC-F01-08）
   撤销：确认摘要「从下一次请求起不能放行；已完成的 2 次放行保持不变，标注『代理放行』」（AC-F01-09）
```

- **多名业主（REQ-F01-06）**：成员中可有多名「业主」；任一业主都能在本卡指定或撤销代理人，记录署名为实际操作人。任一业主签认或放行即生效、其他业主的待办同时消失（AC-F01-10，由签认与放行页落实，本页通过成员列表展示多名业主）。

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 正常态 | 有成员 | 五张卡片 |
| 加载态 | 读取 | 各卡片骨架屏 |
| 空状态 | 新项目还没有成员 | 成员卡：「还没有成员。生成邀请链接，把业主、项目经理等各方拉进项目。」+ 生成邀请；邀请记录卡：「还没有邀请记录」；代理人卡：「未指定代理人」 |
| 错误态 | 读取失败 | 「成员信息加载失败（网络中断），请重试」+ 重试 |

| 已交房 | 状态为已交房 | 状态卡显示实际交房日期，不再有推进按钮 |

| 边界 | 处理 |
| :--- | :--- |
| 移除自己 | 公司管理员不在项目成员内，不会出现；项目经理没有移除权限 |

| 邀请过期 | 超过 7 天自动变为「已过期」，不可复制 |

## 8. 业务规则与校验

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 邀请手机号 | 提交时 | 11 位 | 请输入 11 位手机号 |
| 邀请角色 | 提交时 | 至少 1 个 | 请至少选择一个角色 |
| 邀请公司管理员 | 服务端 | 只有公司管理员可设 | 只有公司管理员可以设置该角色 |
| 业主邀请角色 | 服务端 | 业主只能邀请业主方成员（AC-F02-09） | 业主只能邀请业主方成员 |
| 修改放行时限 | 服务端 | 仅项目经理、公司管理员（AC-F06-17） | 403 无权修改 |
| 编辑角色 | 提交时 | 至少 1 个 | 请至少保留一个角色；如需移出项目请使用「移除」 |
| 实际交房日期 | 提交时 | 推进为已交房时必填 | 请填写实际交房日期 |
| 放行时限 | 提交时 | 1–72 的整数 | 请输入 1–72 之间的整数 |

- **DEC-106（已由 rev2 需求覆盖 → AC-F06-17）**：放行时限由项目经理或公司管理员设置，其他角色只读。原设计决定与 AC-F06-17 一致，实现不变，以 AC-F06-17 为依据。
- **DEC-107（已由 rev2 需求覆盖 → AC-F01-03、AC-F01-12、AC-F02-09）**：「业主方成员」已进入角色清单（AC-F01-03），只读、被业主指定为代理人后才能放行（AC-F01-12）；业主只能邀请该角色（AC-F02-09，rev2 新增，本页已补）。
- **DEC-109（design-derived）**：项目状态只能单向推进（筹备 → 施工中 → 已交房），推进前展示确认摘要。
- **DEC-110（design-derived）**：移除成员、重置密码、撤销邀请、指定 / 更换 / 撤销代理人、推进项目状态都使用「确认内容摘要」二次确认。
- **DEC-111（已由 rev2 需求覆盖 → NFR-006 rev2）**：临时密码只在重置成功的弹窗里一次性显示供公司管理员复制转交，关闭后不可再查看，且不落日志。弹窗文案同步说明「不会写入任何日志」。
- **公司管理员只读（AC-F01-13）**：本页的成员、角色、邀请、重置密码、放行时限均属管理操作，不受影响；公司管理员在本项目其他页面看不到签认、核对、放行、定价按钮。
- 手机号打码：成员与邀请记录中，只有公司管理员看到完整号码（蓝图 §9）。

## 11. 验收标准

| F-08 | 唯一代理人 | 已有代理人时指定新代理人，原代理人权限撤销，新成员成为唯一代理人，记录变更人与时间 | AC-F01-08 |
