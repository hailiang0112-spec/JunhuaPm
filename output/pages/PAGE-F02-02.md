## 2. 页面概述

- **定位**：被邀请人打开邀请链接，确认邀请信息并开通账号或关联已有账号，加入对应项目。
- **存在理由**：平台是邀请制，不依赖短信等外部通道开通账号（US-F02-01）。
- **不做什么**：不做公开注册；不做短信验证码；邀请里的项目和角色由邀请人决定，本页不可修改。

## 3. 用户与场景

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 被邀请人（未来的业主、业主方成员、项目经理、设计经理、质检、预算专员等） |
| 设备 | 手机为主，在微信中点开链接 |

- **场景 A 新用户**：看到「张工（项目经理）邀请你以质检身份加入 君华新城 · 联排别墅装修工程」→ 填写姓名、收到邀请的手机号、设置密码 → 加入并进入我的待办。
- **场景 B 已有账号**：手机号已在平台开通 → 输入现有登录密码确认 → 新项目的角色关联到原账号，不重复建号、不重置密码（AC-F02-02 rev2）。
- **场景 C 失效**：链接已过期、已被使用或已被撤销 → 显示「邀请已失效，请联系邀请人重新发送」，不提供任何表单（AC-F02-03）。

## 4. 信息架构

1. 品牌区。
2. 邀请信息卡：项目名称、邀请人（姓名 + 角色）、授予角色、绑定手机号（打码显示，如 186****2201）、有效期至（一次性）。
3. 加入表单（按新用户 / 已有账号两种形态切换）。
4. 失效态（替换 2、3）。

## 5. 界面内容

**邀请信息**

| 字段 | 示例 | 来源 |

| 邀请人 | 张工 · 项目经理 | 邀请记录 |

| 有效期 | 2026-11-02 14:30 前有效，仅可使用一次 | 生成时间 + 7 天 |

**新用户表单**

| 字段 | 必填 | 规则 |
| :--- | :--- | :--- |
| 姓名 | 是 | 2–20 字，作为签认署名（AC-F02-02 rev2） |
| 手机号 | 是 | 必须与邀请绑定的手机号一致 |
| 设置密码 | 是 | 至少 8 位，同时包含字母和数字（NFR-006） |
| 确认密码 | 是 | 与设置密码一致 |
| 按钮 | — | 「设置密码并加入」 |

**已有账号表单（AC-F02-02 rev2）**

| 字段 | 必填 | 规则 |
| :--- | :--- | :--- |
| 说明 | — | 「该手机号已有账号（王工），输入登录密码即可加入本项目」 |
| 登录密码 | 是 | 校验现有密码 |
| 按钮 | — | 「确认加入」 |

**失效态**：锁形图标 +「邀请已失效，请联系邀请人重新发送」+ 次要链接「已有账号？去登录」。

## 6. 交互流程

```
打开邀请链接
  ├─ 邀请已过期 / 已使用 / 已撤销 → 失效态（AC-F02-03），不创建账号、不授予角色
  └─ 邀请有效 → 显示邀请信息 + 新用户表单
        填写手机号后
          ├─ 与邀请不一致 → 「手机号与邀请不一致，请使用收到邀请的手机号」
          ├─ 该手机号已有账号 → 切换为已有账号表单（AC-F02-02）→ 校验原密码 → 关联
          └─ 新手机号 → 校验姓名、密码规则 → 创建账号
        成功 → 在该项目授予邀请中的角色，邀请标记为已使用 → 提示「已加入 君华新城 · 联排别墅装修工程」→ 进入 PAGE-F16-01
```

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 加载态 | 校验邀请码 | 邀请信息卡骨架屏 |
| 新用户态 | 邀请有效，手机号未开通 | 新用户表单 |
| 已有账号态 | 邀请有效，手机号已开通 | 已有账号表单 |
| 失效态 | 过期、已使用或已撤销 | 统一文案「邀请已失效，请联系邀请人重新发送」 |
| 提交态 | 点击加入 | 按钮不可重复点击 |
| 错误态 | 网络失败 | 「网络异常，请重试」，表单内容保留 |

- 本页没有「无权限」态：邀请码本身就是访问凭据，无效即失效态。
- 并发：同一链接在两台设备同时提交，只有先完成的一次生效，另一台显示失效态（一次性，AC-F02-01）。

## 8. 业务规则与校验

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 姓名 | 提交时 | 必填，2–20 字 | 请填写姓名 |
| 手机号 | 提交时 | 必填且与邀请一致 | 手机号与邀请不一致，请使用收到邀请的手机号 |
| 密码规则 | 提交时 | ≥ 8 位，含字母和数字 | 密码至少 8 位，需同时包含字母和数字 |
| 确认密码 | 提交时 | 与密码一致 | 两次输入的密码不一致 |
| 现有密码 | 服务端 | 已有账号的登录密码 | 密码错误 |

- **DEC-102（已由 rev2 需求覆盖 → AC-F02-02）**：手机号已有账号时输入原密码确认后关联，不重置密码。原理由（防止拿到链接的人改掉他人已有账号的密码）保留作背景。
- **DEC-103（已由 rev2 需求覆盖 → AC-F02-02）**：被邀请人在本页填写本人姓名，作为签认署名。

## 9. 页面流转

```
PAGE-F01-02 生成邀请 → 复制 → 微信发送
        ▼
  邀请落地页 PAGE-F02-02
   ├─ 有效 → 加入成功 → PAGE-F16-01
   └─ 失效 → 联系邀请人 / 去登录 PAGE-F02-01
```
