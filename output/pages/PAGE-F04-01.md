## 2. 页面概述

### 2.1 一句话定位
让设计经理每次改图都写明改了什么、标出受影响的工作项，让业主逐版签认。

### 2.2 存在理由
1. 原先只签最终版，十次改图的过程无据可查。
2. 新版签认后，基于旧版签认的工作项必须重新签认，否则现场按哪版施工说不清（AC-F04-07）。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 改动可追溯 | 第 2 版起 100% 版本带改动说明（AC-F04-02） |
| 签认留痕 | 每次签认生成含签认人、时间、版本号、文件摘要的记录（AC-F04-06） |
| 影响传导 | 新版签认后受影响且已签认的基线 100% 变为待重签并生成待办（AC-F04-07） |

### 2.4 不做什么
- **不做**删除或替换已发布版本（AC-F04-04）。
- **不做**新建分册的管理入口：Source IDs 未定义分册维护；分册来自项目模板（REQ-F03-01）。
- **不做**图纸驳回：Source IDs 只定义签认。
- **不做**业主代理人签认图纸（AC-F01-07）。

## 3. 用户与场景

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 设计经理（上传新版）；业主（签认）；其他成员只读 |
| 使用设备 | 电脑上传为主；业主手机签认 |

**场景 A：设计经理发布新版** — 选分册 → 上传新版 → 选 PDF / 图片（可附 CAD）→ 写「本版改了什么」→ 勾选受影响工作项 → 确认摘要 → 发布，状态「待业主签认」（AC-F04-01）。
**场景 B：业主签认** — 打开待签版本 → 看改动说明、文件、受影响工作项 → 签认 → 确认摘要（含待重签影响）→ 印章盖下「已签认」（AC-F04-06、AC-F04-07）。

## 4. 信息架构
1. 标题区：「图纸」+ 项目、分册数 + 演示身份
2. 分册列表（电脑左列；平板与手机为顶部横向滑动卡片）：分册名、状态印章（有待签版本时「待签认」，否则「已签认」）、当前签认版本与日期
3. 分册详情卡：分册名、当前签认版、「上传新版」（设计经理）、只读说明、版本时间线（新→旧）
4. 上传新版弹窗

## 5. 界面内容

### 5.1 版本时间线条目
- 缩略图、版本号、印章（待签认 `pend` / 已签认 `pass`）、发布人与日期。
- 改动说明（首版显示「首版。」）。
- 文件：图纸文件名与大小；CAD 附件（若有）。
- 签认记录（已签认版本）：「签认记录：刘先生 · 2026-10-16 14:20 · V2 · 文件摘要 SHA-256 9e41 07b2 … c5d8」（AC-F04-06）。
- 受影响工作项（折叠）：数量与「其中基线已签认 N 项」；展开列出楼层、房间、工作项名称与基线状态；已签认的版本显示签认后变为待重签 / 已重签的情况。
- 操作：「签认 Vn」（仅业主、仅待签认版本）、「查看」→ PAGE-F04-02、「与上一版对比」→ PAGE-F04-02。

### 5.2 上传新版弹窗（仅设计经理）
- 标题：「上传新版 · 水电点位图 V4」（版本号 = 上一版 + 1）。
- 图纸文件（必填）：PDF、JPG、PNG，单个不超过 50MB；说明「作为现场查看与检查点钉点的底图」。
- CAD 附件（可选）：.dwg / .dxf；说明「CAD 仅作为附件，不能单独发布」。
- 本版改了什么（第 2 版起必填）。
- 受影响的工作项：本项目工作项多选（楼层 房间 · 名称），显示已勾选数；说明「新版签认后，其中已签认的基线变为待重签」。
- 按钮：取消 / 发布。

### 5.3 示例数据
水电点位图：V1（2026-09-10，已签认 09-12）、V2（2026-10-14，BG-001 新增书房 B 两个插座，已签认 10-16，影响 3 项）、V3（2026-10-25，二楼主卫次卫给水改走顶面等，待业主签认，影响 12 项，其中已签认 9 项）。

## 6. 交互流程

```
设计经理点「发布」
  ├─ 只有 CAD 没有图纸文件 → 「请同时上传 PDF 或图片版，CAD 仅作为附件」（AC-F04-03）
  ├─ 没有任何图纸文件 → 「请上传 PDF 或图片版图纸」（DEC-207）
  ├─ 格式不符 / 超过 50MB → 「文件名：格式不支持，仅支持 PDF、JPG、PNG」/「文件名：超过 50MB」（DEC-207）
  ├─ 第 2 版起无改动说明 → 「请说明本版改了什么」（AC-F04-02）
  └─ 通过 → 确认摘要（版本、文件、附件、改动说明、受影响工作项）（DEC-203）
        └─ 确认 → 生成新版本，状态「待业主签认」，此前版本保持只读（AC-F04-01）

业主点「签认 Vn」→ 确认摘要（分册、版本、文件摘要、改动说明、签认人、时间以服务器为准；
   警示「受影响的 12 个工作项中，基线已签认的 9 项将变为待重签，并向项目经理和业主生成待办」）
   └─ 确认 → 该版本成为当前签认版，生成签认记录，印章盖下（AC-F04-06、AC-F04-07）
```

多名业主时任一业主签认即生效，署名为本人，其他业主的待办同时消失（AC-F01-10）。

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 加载 | 进入页面 | 分册与时间线骨架屏 |
| 空分册 | 分册尚无版本 | 「该分册还没有图纸。」设计经理可见「上传首版」 |
| 有待签版本 | 存在待业主签认版本 | 分册印章「待签认」，业主看到签认按钮 |
| 上传中 | 发布后文件上传 | 发布按钮显示「上传中」，不可重复提交 |
| 错误 | 读取或上传失败 | 「上传失败（网络中断），请重试」，已填内容保留 |
| 无权限 | 非本项目成员 | 跳转 PAGE-F01-03 |

边界：业主代理人、项目经理等看不到签认按钮（AC-F01-07，无权限隐藏）；非设计经理看不到上传新版。

## 8. 业务规则
- 版本号为分册内上一版加 1（AC-F04-01）。
- 只有已签认版本可被基线引用、作为钉点底图（AC-F05-02、AC-F06-01）。
- 签认后受影响且基线已签认的工作项进入待重签，并向项目经理与业主生成待办（AC-F04-07）。
- 版本文件与改动说明发布后不可删除或替换（AC-F04-04）。

## 9. 页面流转
```
导航「图纸」/ 手机标签「图纸」/ PAGE-F16-01 待签图纸 → 本页 → 查看 / 对比 → PAGE-F04-02 图纸查看器
```

## 10. 数据需求

| 数据 | 用途 |
| :--- | :--- |
| 分册列表与各分册当前签认版、待签版本 | 分册列表 |
| 版本（文件、附件、改动说明、发布人、签认记录、受影响工作项及其基线状态） | 时间线 |

## 11. 验收标准

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 上传生成新版（AC-F04-01） | 上传 PDF / JPG / PNG（≤50MB，可附 CAD）并写改动说明后，生成上一版 +1 的新版本，状态「待业主签认」，旧版只读可查 |
| F-02 | 缺改动说明（AC-F04-02） | 第 2 版起未填改动说明，拒绝发布并提示「请说明本版改了什么」 |
| F-03 | 只传 CAD（AC-F04-03） | 只有 CAD 无 PDF / 图片，拒绝发布并提示「请同时上传 PDF 或图片版，CAD 仅作为附件」 |
| F-04 | 签认成为当前签认版（AC-F04-06） | 业主签认后该版为当前签认版，生成含签认人、时间、版本号、文件摘要的记录 |
| F-05 | 受影响工作项待重签（AC-F04-07） | 新版签认后，勾选的工作项中已签认的基线变为「待重签」，项目经理与业主收到待办 |
| F-06 | 版本只读（AC-F04-04） | 时间线无删除、替换入口 |
| F-07 | 签认权限（AC-F01-07） | 业主代理人及其他非业主角色看不到签认按钮 |
| F-08 | 上传失败反馈（DEC-207） | 格式不符或超过 50MB 时显示文件名与原因 |
| U-01 | 二次确认（DEC-203） | 签认与发布都先显示确认摘要；签认成功时印章盖章动效 |
| U-02 | 手机可用 | 375px 下页面无横向滚动，分册卡片在自身区域横向滑动 |
