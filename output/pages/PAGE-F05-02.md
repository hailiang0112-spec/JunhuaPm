## 2. 页面概述

### 2.1 一句话定位
让业主在开工前逐项看清图纸版本、做法、费用、日期、质检人和检查点后签认，或写明理由退回。

### 2.2 存在理由
1. 「先讲清再干活」：签认的基线是日后一切争议的对照依据。
2. 工作项多，逐条操作太慢；批量签认必须仍然逐项留痕（AC-F05-04）。
3. 临近施工仍未签认的工作项要醒目提示，避免边干边定（AC-F05-09）。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 先看后签 | 100% 签认发生在该项完整内容展开之后（AC-F05-03） |
| 逐项留痕 | 批量签认 N 项生成 N 条独立签认记录（AC-F05-04） |
| 手机可用 | 375px 下页面无横向滚动（NFR-001） |

### 2.4 不做什么
- **不做**基线编辑：在 PAGE-F05-01 由项目经理完成。
- **不做**跨工段、跨楼层混合批量签认：AC-F05-04 限定同一工段或同一楼层。
- **不做**业主代理人签认（AC-F01-07）。

## 3. 用户与场景

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 业主（签认、退回）；业主代理人、业主方成员（AC-F01-12）与其他角色只读；公司管理员对业务数据只读，看不到签认、退回（AC-F01-13） |
| 使用设备 | 手机、电脑 |

**场景 A：按工段批量签认（主场景）** — 选「按工段」→ 在砌墙工段逐项展开查看 → 勾选 → 「签认本组所选」→ 确认摘要 → 印章盖下。
**场景 B：退回** — 展开某项 → 「退回」→ 填写理由 → 确认摘要 → 状态「已退回」，项目经理收到待办（AC-F05-05）。
**场景 C：处理即将施工项** — 标有「即将施工，基线未签认」的项优先查看（AC-F05-09）。

## 4. 信息架构
1. 标题区：「基线签认」+ 待签认数、合计金额 + 演示身份
2. 角色说明横幅（按角色显示不同文案）
3. 分组切换：按工段 / 按楼层；右侧显示已选数量与所在组
4. 分组卡（每组一张）：组名、待签数、「签认本组所选（n）」；组内条目列表
5. 退回弹窗

## 5. 界面内容

### 5.1 条目（折叠态）
- 勾选框：展开前不可用，提示「请先展开查看完整内容」（DEC-205、AC-F05-03）。
- 楼层 房间 · 工作项名称；次行：楼层或工段、计划完成日期、图纸分册版本、标签。
- 标签：「重签」（基线因新版图纸重新提交，DEC-206）、「即将施工，基线未签认」（计划完成日期距今 ≤ 7 天，AC-F05-09）。
- 费用（元）、状态印章（待签认 `pend` / 已签认 `pass`），已退回为普通红色标签。
- 「展开查看 / 收起」。

### 5.2 条目（展开态）— 完整内容（AC-F05-03）
图纸分册与版本（已签认）、工作说明、验收标准、费用、计划完成日期、质检人、检查点清单（编号、名称、是否隐蔽）。展开后才显示：「签认此项」「退回」（仅业主），以及「打开工作项」→ PAGE-F05-01。

### 5.3 横幅文案
- 业主：「逐项展开看完全部内容后才能签认。可勾选同一工段或同一楼层的多项一起签认，每项都会生成独立的签认记录。本项目任一业主签认即生效，记录署名为你本人，其他业主的同一待办同时消失。」（AC-F01-10）
- 业主代理人：「业主代理人只能放行检查点，不能签认或退回基线。以下内容仅供查看。」
- 业主方成员：「业主方成员只能查看，不能签认或退回基线。以下内容仅供查看。」（AC-F01-12）
- 其他角色：「基线由业主签认或退回。待签认期间基线锁定，需业主退回后才能修改；被退回的基线会出现在项目经理的待办中。」（AC-F05-10：项目经理要改待签认基线，只能请业主在本页退回）

### 5.4 示例数据
砌墙：三楼主卧隔墙砌筑 6,420 元（2026-11-02，即将施工）、三楼次卧隔墙砌筑 4,980 元（2026-11-03，即将施工）、三楼卫生间防水反坎浇筑 1,260 元、二楼书房 B 强电插座布线 980 元（重签，引用水电点位图 V2）；水电：一楼厨房给排水管道敷设 3,850 元、一楼客厅强电线管敷设 2,730 元、二楼主卫给水管道敷设 2,160 元。合计 22,380 元。

## 6. 交互流程

```
业主展开条目 → 勾选框可用、出现「签认此项」「退回」
勾选另一组的条目 → 清空前一组选择并提示「批量签认只能在同一工段（楼层）内勾选」（DEC-205）
点「签认本组所选（n）」/「签认此项」
  → 确认摘要：逐项列出名称、图纸版本、费用、日期、检查点数；合计；签认人
     说明「将生成 n 条独立签认记录，每条包含签认人、时间和该项基线的完整内容快照」
  → 确认 → 每项生成签认记录，印章变「已签认」（盖章动效）（AC-F05-04）
点「退回」→ 弹窗填写理由（必填）→ 确认摘要（基线、理由、操作人）
  → 确认 → 状态「已退回」，理由随基线保存，项目经理收到待办（AC-F05-05）
切换分组 → 清空选择
```

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 加载 | 进入页面 | 分组卡骨架屏 |
| 空 | 没有待签基线 | 「没有待签认的基线。」 |
| 只读 | 非业主身份 | 无勾选框和签认、退回按钮，可展开查看 |
| 错误 | 读取或提交失败 | 「提交失败，请重试」，选择保留 |
| 无权限 | 非本项目成员 | 跳转 PAGE-F01-03 |

| 边界场景 | 处理策略 |
| :--- | :--- |
| 另一名业主已先签认 | 该项从待签列表消失；若提交时已签认，提示已由某人签认，不重复生成记录（AC-F01-10） |
| 退回理由为空 | 「请填写退回理由」，不提交 |

## 8. 业务规则
- 签认只对业主开放（AC-F01-07）；业主方成员、公司管理员只读（AC-F01-12、AC-F01-13）。
- 待签认期间基线锁定，项目经理在 PAGE-F05-01 修改会被拒绝并提示「基线待业主签认，需业主退回后才能修改」；退回是解锁的唯一途径（AC-F05-10、AC-F05-05）。
- 批量签认范围限同一工段或同一楼层，每项独立签认记录与内容快照（AC-F05-04）。
- 「即将施工，基线未签认」：计划完成日期距今不超过 7 天且基线未签认（AC-F05-09），同时向项目经理和业主生成待办。

## 11. 验收标准

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 先展开后签认（AC-F05-03） | 未展开的条目不能勾选、无签认按钮；展开后逐项显示图纸分册与版本、工作说明、验收标准、费用、计划完成日期、质检人、检查点清单 |
| F-02 | 批量逐项记录（AC-F05-04） | 同组勾选 N 条并确认后生成 N 条独立签认记录，各含签认人、时间和完整内容快照 |
| F-03 | 退回（AC-F05-05） | 填写理由后状态变「已退回」，理由随基线保存，项目经理收到待办 |
| F-04 | 即将施工提示（AC-F05-09） | 计划完成日期距今 ≤ 7 天且未签认的条目显示「即将施工，基线未签认」 |
| F-05 | 多名业主（AC-F01-10） | 任一业主签认即生效，署名为本人，其他业主的对应待办消失 |
| F-06 | 同组限制（DEC-205） | 跨组勾选时清空前一组选择并提示 |
| F-07 | 代理人只读（AC-F01-07） | 业主代理人看不到勾选、签认、退回 |
| F-08 | 只读角色（AC-F01-12、AC-F01-13） | 业主方成员、公司管理员看不到勾选、签认、退回 |
| F-09 | 待签认锁定说明（AC-F05-10） | 非业主身份横幅说明待签认期间锁定、需业主退回后修改 |
| U-01 | 二次确认 | 签认、退回都先显示确认摘要；签认成功时印章盖章动效 |
| U-02 | 手机可用（NFR-001） | 375px 下无横向滚动，组签认按钮通栏 44px |
