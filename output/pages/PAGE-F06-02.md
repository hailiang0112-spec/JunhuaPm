## 2. 页面概述

### 2.1 一句话定位
在隐蔽工序被盖住前，让质检对照签认图拍照给出结论，让业主或业主代理人凭这条证据放行。

### 2.2 存在理由
1. 没有这个页面，「盖住前对图检查 → 业主放行」这一主线没有落点，偏差只能在盖住后才发现。
2. 核对、放行、覆盖都要留下不可修改的记录，才能在争议时对照。
3. 质检在工地手机上操作，弱网下照片容易上传失败，必须能重传而不丢内容。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 现场可用 | 360–430px 宽下无页面级横向滚动，可直接调起相机（NFR-001） |
| 证据完整 | 100% 核对记录至少含 1 张照片、图纸版本、结论、覆盖状态（AC-F06-02、AC-F06-03） |
| 放行合规 | 未核对、不一致的检查点 0 次被放行；非业主方 0 次放行成功（AC-F06-07、AC-F06-08） |

### 2.4 不做什么
- **不做**核对记录的修改或删除：更正只能再次核对追加（AC-F06-05、REQ-F17-01）。
- **不做**超时自动放行：超时只提醒（AC-F06-13）。
- **不做**检查点的新建与钉点位置修改：在 PAGE-F05-01 的基线内完成（AC-F06-01）。
- **不做**问题处置（原因、闭环、重开）：由 PAGE-F08-01 承担。
- **不做**核对表单的自由备注字段：Source IDs 未定义；不一致的原因在问题页登记。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 质检（核对、修正发现时点）；业主、业主代理人（放行）；项目经理（标记已覆盖、修正发现时点）；业主方成员只读，被业主指定为代理人后按业主代理人放行（AC-F01-12）；公司管理员只读，看不到核对、放行按钮（AC-F01-13）；其他角色只读 |
| 使用设备 | 以手机为主，电脑查看 |
| 使用姿势 | 工地现场单手持机，可能戴手套、强光、弱网 |

### 3.2 核心使用场景

**场景 A：质检盖住前对图核对（主场景）**
- 前置：检查点已在基线中定义并钉在签认版图纸上。
- 动作：打开检查点 → 看图上钉点 → 拍照（至少 1 张）→ 选结论与覆盖状态 → 看确认摘要 → 提交。

**场景 B：业主放行**
- 前置：当前结论为「一致」或「已变更」。
- 动作：从待办进入 → 看依据的核对记录与照片 → 放行 → 确认摘要 → 印章盖下「已放行」。

**场景 C：弱网上传失败（兜底）**
- 照片上传失败保留在本机草稿，点「重传」；全部成功后才能提交。

**场景 D：项目经理登记覆盖**
- 下一道工序开始前标记已覆盖；若此时未放行，系统记「未放行先覆盖」事件。

### 3.3 用户核心诉求
1. **快**：现场几步完成，按钮够大。
2. **不丢**：网断了照片和已选内容还在。
3. **说得清**：放行依据哪条核对、谁放的、是不是代理，一眼可见。

## 4. 信息架构

手机端单列从上到下：检查点卡 → 业主放行卡 → 图上钉点 → 对图核对表单 → 覆盖登记 → 核对与放行历史。电脑端左列（检查点、图上钉点、历史），右列（放行、核对表单、覆盖登记）。

1. 面包屑 + 标题区（编号、名称、工段 · 楼层 · 房间 · 是否隐蔽 · 质检人）+ 演示身份
2. 待重签横幅（工作项基线处于待重签时显示，AC-F05-07）
3. 检查点卡：状态印章（DEC-201）、检查要点、钉点图纸、当前结论、覆盖状态、所属工作项
4. 业主放行卡：放行状态印章、等待时长、依据的核对记录、放行按钮或原因、放行记录
5. 图上钉点：所用签认版图纸平面 + 本检查点钉点高亮
6. 对图核对表单（仅质检）
7. 覆盖登记（仅项目经理）
8. 核对与放行历史：核对记录、放行记录、未放行先覆盖事件、发现时点修正记录，倒序

## 5. 界面内容

### 5.1 元素清单

**检查点卡印章**（DEC-201，一张卡只显示一个）
- 放行后发现不一致 / 不一致 / 未放行先覆盖 / 不得覆盖（`stop`），待放行（`pend`），已放行（`pass`），代理放行（`proxy`）。
- 隐蔽且未放行、未覆盖时显示「不得覆盖」（AC-F06-11）。

**业主放行卡**
- 印章：超时（`stop`，待放行超过项目时限，AC-F06-13）/ 待放行（`pend`）/ 已放行 / 代理放行；不能放行时显示当前结论。
- 等待行：「待放行 · 已等 N 小时（项目时限 24 小时；超时只提醒，不会自动放行）」。
- 依据行：「依据 核对 #n · 核对人 · 时间 · 结论 · 照片数」。
- 放行按钮：通栏 44px，仅业主、业主代理人可见（AC-F06-08，无权限隐藏）；代理人身份下提示「记录标注代理放行」（AC-F01-07）。
- 非业主方角色看到说明「只有业主或业主代理人可以放行。」
- 业主方成员（未被指定为代理人）看到说明「业主方成员只能查看；被业主指定为业主代理人后才能放行。」，无放行按钮（AC-F01-12）。
- 原因区（DEC-208）：当前结论为未核对或不一致时不显示按钮，显示「当前结论为「不一致」，不能放行。质检复核为「一致」或「已变更」后才能放行。」（AC-F06-07）
- 放行记录：放行人、是否代理、服务器时间、依据的核对记录（AC-F06-06）。

**图上钉点**
- 底图：工作项基线引用的签认版；基线待重签时仍为原签认版（AC-F05-07）。
- 文案：「底图：水电点位图 V1（本工作项基线引用的签认版）· 坐标 (740, 390)」；「在查看器中打开」→ PAGE-F04-02。

**对图核对表单**（仅质检）
- 本机草稿条（DEC-204）：「已自动保存为本机草稿 · 时间」+「放弃草稿」。
- 现场照片（必填，≥1 张）：「拍照」（调起后置相机）、「相册」；每张缩略图显示「已上传 / 上传中 / 上传失败 + 重传」，可移除。
- 照片钉点说明：「照片钉点：书房 B 东墙（沿用检查点钉点，所用图纸 水电点位图 V1）」。
- 结论（必填，单选 44px）：一致 / 不一致 / 已变更。
- 关联已生效的变更单（结论为「已变更」时出现且必填）：只列已由业主签认生效的变更单（AC-F06-04）。
- 核对时是否已被覆盖（必填）：未覆盖 / 已被覆盖；选「已被覆盖」且未放行时提示「该检查点尚未放行，提交后将记录一条「未放行先覆盖」事件。」
- 提交按钮：「提交核对记录」，通栏 44px。

**覆盖登记**（仅项目经理）
- 文案：当前覆盖状态；按钮「标记已覆盖」（通栏 44px，危险样式）。

**核对与放行历史**
- 核对记录：编号、结论标签、核对人、服务器时间、所用图纸版本、覆盖状态、照片缩略图与钉点位置；不一致时含发现时点与生成的问题链接（PAGE-F08-01）；已变更时含关联变更单（PAGE-F07-02）。
- 不一致记录上「修正发现时点」按钮（质检、项目经理可见）；修正记录以「修正：原值 → 新值 · 修正人 · 时间 · 理由」追加在该记录下。
- 未放行先覆盖事件：检查点、时间、记录人。

### 5.2 辅助信息
- 历史卡标题旁「只追加，不可修改」。

## 6. 交互流程

### 6.1 页面加载
- 读取检查点、当前结论（最新一条核对，AC-F06-05）、放行与覆盖状态、所属工作项基线状态。
- 质检身份下若存在本机草稿，恢复照片与已选项并显示草稿条（DEC-204）。

### 6.2 核对提交

```
质检点「提交核对记录」
  ├─ 无照片 → 「至少上传 1 张现场照片」（AC-F06-02）
  ├─ 有照片未上传成功 → 「还有 N 张照片未上传成功，请重传后再提交（已保存在本机草稿）」（DEC-204）
  ├─ 未选结论 / 覆盖状态 → 列出全部缺项
  ├─ 结论「已变更」未关联 → 「请关联已生效的变更单」（AC-F06-04）
  └─ 通过 → 确认摘要（核对人、时间以服务器为准、图纸版本、照片数与钉点、结论、覆盖状态；
            不一致时含推断的发现时点和「将自动生成问题」；未放行且已覆盖时提示未放行先覆盖）（DEC-203）
        └─ 确认 → 追加核对 #n（不可修改）→ 当前结论更新
              ├─ 不一致 → 推断发现时点（AC-F06-14）→ 生成未闭环问题（AC-F08-01）
              │           └─ 若已放行 → 状态「放行后发现不一致」，原放行记录保留（AC-F06-10）
              ├─ 已被覆盖且此前未放行 → 生成「未放行先覆盖」事件（AC-F06-12）
              └─ 清空表单与本机草稿
```

### 6.3 放行

```
业主 / 业主代理人点「放行」
  ├─ 当前结论为未核对或不一致 → 不显示按钮，显示原因（AC-F06-07，DEC-208）
  └─ 确认摘要（检查点、依据核对、放行人及是否代理、时间以服务器为准）
        └─ 确认 → 生成放行记录 → 印章盖下「已放行」/「代理放行」（.just）
并发：他人已先放行 → 不生成新记录，提示「已由某人于某时放行，未生成新的放行记录」（AC-F06-09）
代理被撤销后：原代理人下一次请求起放行被拒，已完成记录仍标「代理放行」（AC-F01-09）
```

### 6.4 标记已覆盖
项目经理点「标记已覆盖」→ 确认摘要（检查点、放行状态、记录人、时间）；未放行时警示将记「未放行先覆盖」→ 确认 → 记录覆盖，未放行时生成事件并进入业主待办（AC-F06-12）。

### 6.5 修正发现时点
质检或项目经理在不一致记录上点「修正发现时点」→ 弹窗显示系统推断依据，选择新值、填写理由（必填）→ 确认摘要（修正前后值、修正人、理由）→ 追加修正记录（AC-F06-15）。

## 7. 状态与边界

### 7.1 页面状态

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 加载 | 进入页面 | 各卡骨架屏 |
| 未核对 | 无核对记录 | 放行卡显示原因；隐蔽时印章「不得覆盖」 |
| 待放行 / 超时 | 结论一致或已变更且未放行 | 放行卡「待放行」，超过时限变「超时」 |
| 不一致 | 最新结论不一致 | 印章「不一致」，放行卡显示原因，历史中有问题链接 |
| 已放行 / 代理放行 | 有放行记录 | 印章 pass / proxy，放行记录可见 |
| 放行后发现不一致 | 已放行后追加不一致核对 | 印章「放行后发现不一致」，原放行记录保留 |
| 未放行先覆盖 | 未放行时被标记覆盖 | 印章「未放行先覆盖」，历史有事件 |
| 待重签 | 所属工作项基线待重签 | 顶部横幅，底图为原签认版 |
| 错误 | 读取失败 | 「加载失败，请重试」+ 重试按钮 |
| 无权限 | 非本项目成员访问 | 跳转 PAGE-F01-03 无权限页 |
| 空历史 | 尚无任何记录 | 历史卡显示「还没有核对记录」 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 弱网照片上传失败 | 保留本机，可单张重传；未全部成功不能提交（DEC-204） |
| 离开未提交的核对表单 | 内容已存本机草稿，下次打开恢复 |
| 两人同时放行 | 只保留第一条，后者提示已由某人放行（AC-F06-09） |
| 代理被撤销 | 下一次请求起不能放行（AC-F01-09） |
| 非业主方调用放行 | 服务端拒绝「只有业主或业主代理人可以放行」（AC-F06-08、NFR-003） |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| 核对记录 | 核对人、服务器时间、所用图纸版本、照片与钉点位置、结论、覆盖状态；提交后不可修改（AC-F06-03） |
| 当前结论 | 最新一条核对记录的结论（AC-F06-05） |
| 放行记录 | 放行人、是否代理、时间、所依据的核对记录（AC-F06-06） |
| 发现时点 | 覆盖前 / 覆盖后 / 交房后；推断规则见 8.3 |
| 覆盖时间 | 项目经理首次标记已覆盖与质检核对选「已被覆盖」中较早者（PRD §3.2.1） |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 照片 | 提交时 | ≥ 1 张 | 至少上传 1 张现场照片 |
| 照片上传状态 | 提交时 | 全部上传成功 | 还有 N 张照片未上传成功，请重传后再提交（DEC-204） |
| 已变更关联 | 提交时 | 必须关联已生效变更单 | 请关联已生效的变更单 |
| 放行前提 | 放行时 | 当前结论为一致或已变更 | 提示原因（AC-F06-07） |
| 放行角色 | 放行时 | 业主或业主代理人 | 只有业主或业主代理人可以放行 |
| 修正理由 | 修正时 | 必填 | 请填写修正理由 |

### 8.3 特殊业务规则
- **发现时点推断**（AC-F06-14）：核对日期不早于交房日期（有实际交房日期取实际，否则取计划）→「交房后」；否则核对时未覆盖 →「覆盖前」，已覆盖 →「覆盖后」。示例项目计划交房 2027-08-30，未登记实际交房日期。
- **超时**：待放行超过项目时限（默认 24 小时，可设 1–72 小时）显示「超时」，不自动放行（AC-F06-13）。
- **多名业主**：任一业主放行即生效，署名为本人（AC-F01-10）。

| 发现时点修正（新值、理由） | 确认修正 |

### 10.3 明确排除的数据
- 不提交核对时间：一律取服务器时间（NFR-008）。
- 不提交问题原因与处置：在 PAGE-F08-01 完成。

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 无照片拒绝（AC-F06-02） | 未上传照片提交时提示「至少上传 1 张现场照片」，不生成记录 |
| F-02 | 核对记录内容（AC-F06-03） | 提交后记录含核对人、服务器时间、图纸版本、照片与钉点、结论、覆盖状态，页面无修改入口 |
| F-03 | 已变更须关联（AC-F06-04） | 选「已变更」未关联时提示「请关联已生效的变更单」；选项只含已生效变更单 |
| F-04 | 复核追加（AC-F06-05） | 再次核对新增 #n，当前结论取最新，旧记录仍在历史中 |
| F-05 | 放行（AC-F06-06） | 结论一致或已变更时，业主或代理人确认后生成放行记录，状态变已放行 |
| F-06 | 不能放行（AC-F06-07） | 未核对或不一致时无放行按钮，显示原因 |
| F-07 | 非业主方（AC-F06-08） | 项目经理、设计经理、质检、预算专员、公司管理员看不到放行按钮；接口调用被拒并提示「只有业主或业主代理人可以放行」 |
| F-08 | 重复放行（AC-F06-09） | 已放行后再次提交，不生成第二条记录，提示「已由某人于某时放行」 |
| F-09 | 放行后不一致（AC-F06-10） | 已放行后追加不一致核对，状态变「放行后发现不一致」，原放行记录保留并生成问题 |
| F-10 | 未放行先覆盖（AC-F06-12） | 未放行时项目经理标记已覆盖或质检选「已被覆盖」，生成事件（检查点、时间、记录人）并进入业主待办 |
| F-11 | 发现时点推断（AC-F06-14） | 不一致记录的发现时点按 8.3 规则计算 |
| F-12 | 发现时点修正（AC-F06-15） | 填写理由后保存新值，并追加含修正前后值、修正人、时间、理由的记录 |
| F-13 | 自动生成问题（AC-F08-01） | 不一致提交后生成未闭环问题，带检查点、工作项、楼层、房间、照片、发现时点，可跳转 PAGE-F08-01 |
| F-18 | 业主方成员与公司管理员只读（AC-F01-12、AC-F01-13） | 业主方成员看不到放行按钮并看到「被指定为业主代理人后才能放行」说明；公司管理员看不到核对表单、放行、标记已覆盖、修正发现时点；服务端对二者的放行、核对请求返回 403 |
| F-14 | 代理放行（AC-F01-07、AC-F01-09） | 代理人放行的记录标注「代理放行」；撤销代理后下一次请求起不能放行，已有记录不变 |
| F-15 | 待重签核对（AC-F05-07） | 工作项基线待重签时，底图为原签认版且顶部显示「该工作项有新版图纸待重签」 |
| F-16 | 草稿与重传（DEC-204） | 上传失败的照片可重传；未全部成功不能提交；刷新后草稿恢复 |
| F-17 | 二次确认（DEC-203） | 核对、放行、标记已覆盖、修正发现时点均先显示确认摘要，确认后才提交 |
