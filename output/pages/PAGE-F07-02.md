## 2. 页面概述

### 2.1 一句话定位
一张变更单从发起、定价到业主签认或驳回的全过程都在这一页完成并留痕。

### 2.2 存在理由
1. 口头约定事后对不上：必须写清内容、费用、工期和承担方，并由业主签认。
2. 签认生效后要自动修订受影响基线，否则现场核对会继续按旧基线判「不一致」。
3. 需要新图的变更要提醒设计经理出图，避免图纸落后于现场。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 字段完整 | 缺任一必填项时 100% 拒绝提交并列出全部缺失项 |
| 签认可追溯 | 每次定价、签认、驳回都在流转记录中留下操作人和时间 |

### 2.4 不做什么
- 不允许修改或删除处于待预算定价、待业主签认、已生效状态的变更单，也不允许删除任何变更单——变更单状态属于关键记录（REQ-F17-01）。唯一的修改入口是「已驳回」后的「修改后重新提交」，且只追加新流转记录，不改动已有记录（AC-F07-09）。
- 业主代理人不能签认——代理人只获得放行权限（PRD §2.1）。

## 3. 用户与场景

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 项目经理（发起、驳回后修改重新提交）、预算专员（定价）、业主（签认/驳回）；其他成员只读，含业主方成员（AC-F01-12）；公司管理员看不到定价、签认、驳回按钮（AC-F01-13） |
| 使用设备 | 业主多用手机；项目经理、预算专员手机或电脑 |

**场景 A：项目经理发起**（REQ-F07-01）：填写原因类别、内容、受影响工作项、是否需新图、现场是否已施工 → 提交 → 状态「待预算定价」，预算专员收到待办。
**场景 B：预算专员定价**（REQ-F07-02）：填费用增减、工期影响、承担方 → 状态「待业主签认」，业主收到待办。
**场景 C：业主签认**（REQ-F07-03）：核对确认摘要 → 签认 → 已生效，基线追加修订；需新图时提醒设计经理（REQ-F07-04）。
**场景 D：业主驳回**：填写理由 → 已驳回，项目经理收到待办。
**场景 F：驳回后修改重新提交**（AC-F07-09）：项目经理打开已驳回的 BG-005 →「修改后重新提交」→ 表单预填原内容，顶部显示上次驳回理由 → 修改 → 确认摘要（编号不变、回到待预算定价、驳回记录保留）→ 状态「待预算定价」，预算专员收到待办；签认区下方显示「历史驳回 N 次」，流转记录保留原驳回条目。
**场景 E：从问题或补充事项生成草稿**（AC-F08-02、AC-F13-02）：系统预填内容与附件，项目经理补齐后提交。

## 5. 界面内容

### 5.1 发起表单字段（AC-F07-01、AC-F07-08）

| 字段 | 类型 | 必填 | 规则 / 文案 |
| :--- | :--- | :--- | :--- |
| 原因类别 | 单选 4 项 | 是 | 业主要求 / 设计深化 / 现场条件 / 施工纠偏 |
| 变更内容 | 多行文本 | 是 | 占位「写清在哪里、改什么、改成什么」 |
| 受影响工作项 | 可搜索多选列表（楼层 · 房间 · 工作项（工段）） | 至少 1 个 | 显示「已选 N 个」 |
| 是否需要新版图纸 | 单选 需要 / 不需要 | 是 | — |
| 现场是否已按此施工 | 单选 已施工 / 未施工 | 是 | 选「已施工」时显示：「将标记为『后补变更』：计入『变更先签后做比例』的分母，不计入分子。」 |
| 附件 | 文件 | 否 | design-derived DEC-072：单个不超过 50MB；从来源生成时预填来源附件 |

### 5.2 预算定价字段（AC-F07-03）

| 字段 | 类型 | 必填 | 规则 |
| :--- | :--- | :--- | :--- |
| 费用增减（元） | 整数 | 是 | 可为负数；展示时增加带「+」（红）、减少带「−」（绿） |
| 工期影响（天） | 整数 | 是 | 可为 0 或负数 |
| 费用承担方 | 单选 | 是 | 业主 / 装修公司 / 设计方 |

### 5.3 签认区
- 待业主签认 + 业主：「签认变更单」（主按钮）、「驳回」（危险按钮）；说明「签认后变更单立即生效，并在每个受影响工作项的基线中追加一条引用本变更单的修订；驳回须填写理由。」
- 待业主签认 + 其他角色：提示「等待业主签认。」
- 待预算定价：提示「定价完成后由业主签认。」
- 已生效：「刘先生（业主）已于 {时间} 签认，变更单已生效。」+「基线追加修订」清单（工作项 · 追加修订 · 引用编号 · 时间）。
- 已驳回：红色提示含驳回人、时间、理由，及「已退回项目经理 张工 处理，可修改后重新提交」；项目经理另见「修改后重新提交」按钮（AC-F07-09）。
- 曾被驳回、已重新提交：签认区显示「历史驳回 N 次（记录保留）：第 1 次 刘先生 2026-10-21 21:03，理由：…」。

### 5.4 新版图纸卡（仅「需要新版图纸」时显示，AC-F07-07）
- 生效前：「生效后将向设计经理 李工 生成『按变更单出新版图纸』待办，发布新版时可关联本变更单。」
- 生效后未出图：「已向设计经理 李工 生成『按变更单出新版图纸』待办……」
- 已出图：显示关联的新版名称和发布日期 + 「查看图纸分册」→ PAGE-F04-01。
- 已驳回：「变更单已驳回，不需要出新版图纸。」

### 5.5 流转记录
时间线：发起、定价（含三项结果）、签认生效 / 驳回、修改后重新提交（含第几次提交）、出图关联；每条显示操作人（角色）与时间；底注「流转与签认记录只能追加，不能修改或删除。」

### 5.6 示例数据
BG-003 一楼厨房烟道预留位调整（纠正偏移 120mm）：设计深化；受影响工作项 3 个（一楼厨房烟道包封砌筑、东墙砌筑、排烟管预留孔洞）；需新图；未施工；+1,800 元 / +1 天 / 设计方；待业主签认；来源问题 WT-019（检查点 CK-027）。

## 6. 交互流程

### 6.1 页面加载
- 带编号：加载该变更单，按状态与当前角色渲染定价区、签认区。编号不存在显示「找不到这张变更单」。
- `new`：项目经理显示空表单；其他角色显示「仅项目经理可以发起变更单」。
- `new` + `from`：按 DEC-071 加载已生成的草稿，预填来源内容、受影响工作项与附件，显示来源提示。

### 6.2 核心流程
```
发起：提交
  ├─ 缺字段 → 字段标红 + 顶部「还缺 N 项，不能提交：原因类别、…」（AC-F07-01）
  └─ 齐全 → 生成项目内序号，状态「待预算定价」，向预算专员生成待办（AC-F07-02）
           └─ 选了「已施工」→ 标记「后补变更」（AC-F07-08）
定价（预算专员，状态=待预算定价）：提交
  ├─ 缺项 → 对应字段提示
  └─ 齐全 → 状态「待业主签认」，向业主生成待办（AC-F07-03）
签认（业主）：点「签认变更单」→ 确认摘要（编号与标题、原因类别、费用、工期、承担方、受影响工作项、签认后的影响）→ 确认
  → 状态「已生效」+ 签认记录 + 每个受影响工作项基线追加引用本单的修订（AC-F07-04）
  → 需新图时向设计经理生成「按变更单出新版图纸」待办（AC-F07-07）
驳回（业主）：点「驳回」→ 弹窗含摘要与理由输入 → 确认
  ├─ 理由为空 → 「请填写驳回理由」，不提交（AC-F07-05）
  └─ 有理由 → 状态「已驳回」，理由保存，向项目经理生成待办（AC-F07-06）
修改后重新提交（项目经理，状态=已驳回）：点「修改后重新提交」→ 表单预填 → 修改 → 校验同发起（AC-F07-01）
  → 确认摘要（编号不变、修改后的字段、「回到待预算定价，原定价作废」、「原驳回记录与理由保留」）→ 确认
  → 编号不变，状态「待预算定价」，追加流转记录「修改后重新提交」，向预算专员生成待办；原驳回记录与理由留在历史中（AC-F07-09）
```
签认、驳回与重新提交成功后印章播放盖章动效并显示提示条。

### 6.3 辅助操作
- 发起表单有未提交内容时离开页面，浏览器拦截确认（蓝图 §5）。
- 受影响工作项支持按楼层、房间、名称搜索，已选项在搜索时保留。

## 7. 状态与边界

### 7.1 页面状态

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 加载 | 请求中 | 骨架屏 |
| 错误 | 网络中断 | 「变更单加载失败（网络中断）」+ 重新加载；表单内容保留 |

### 7.2 边界与容错

| 场景 | 处理 |
| :--- | :--- |
| 负数费用或工期 | 允许，按符号显示颜色 |
| 业主代理人、业主方成员打开待签认单 | 不显示签认/驳回，只显示「等待业主签认」 |
| 重新提交后的定价 | 上一轮定价作废，需预算专员重新定价；上一轮定价在流转记录中保留 |
| 已驳回单被重复重新提交 | 服务端锁行判断状态必须为「已驳回」，第二次提交返回 409 |
| 多名业主 | 任一人签认即生效，其他业主的待办同步消失（PRD §5.2，AC-F01-10 口径） |

## 8. 业务规则与校验

### 8.1 状态流转
```
（草稿，DEC-071）──提交──→ 待预算定价 ──定价──→ 待业主签认 ──签认──→ 已生效
                             ↑                     └──驳回──→ 已驳回
                             └──── 修改后重新提交（编号不变，AC-F07-09）────┘
```

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 发起必填 | 提交时 | 5 个必填字段全部有值，工作项 ≥ 1 | 列出全部缺失字段（AC-F07-01） |
| 定价必填 | 提交时 | 3 项都填，工期为整数 | 「请填写费用增减」「请填写工期影响（整数天）」「请选择费用承担方」 |
| 驳回理由 | 确认驳回时 | 非空 | 「请填写驳回理由」（AC-F07-05） |
| 重新提交 | 提交时 | 状态必须为已驳回；字段规则同发起 | 列出全部缺失字段；状态已变时提示刷新（AC-F07-09） |

### 8.3 特殊规则
- 后补变更计入「变更先签后做比例」分母、不计分子（AC-F07-08）。
- 设计补充 **DEC-071（design-derived）**：从问题「一键生成变更单草稿」或补充事项「转为变更单」时，系统立即保存草稿并分配编号，以便来源记录显示关联编号（AC-F13-02）；草稿提交后进入「待预算定价」。直接点「发起变更单」时在提交成功后分配编号。
- 设计补充 **DEC-072（design-derived）**：发起表单提供可选附件（单个不超过 50MB），来源附件自动带入（AC-F13-02 要求预填附件）。
