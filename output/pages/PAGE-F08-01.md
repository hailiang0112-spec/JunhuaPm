## 2. 页面概述

### 2.1 一句话定位
把核对不一致和现场发现的问题集中登记，按规则定责、给出处置方向，并闭环到底。

### 2.2 存在理由
1. 不一致发生后各方扯皮：需要按原因给出确定的处置建议（解题动作 ④）。
2. 问题不闭环、不追踪超期，会在覆盖后变成纠纷。
3. 删除问题会毁掉证据：只能作废并留痕。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 超期可见 | 未闭环问题 100% 显示超期天数，按超期从大到小排在前 |
| 闭环有据 | 由不一致生成的问题 100% 须复核后才能闭环 |

### 2.4 不做什么
- 不物理删除问题（AC-F08-07）。
- 不在本页做核对或复核——复核在检查点详情 PAGE-F06-02 完成。
- 不在本页审核经验条目——审核在 PAGE-F09-01。

## 3. 用户与场景

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 质检（选原因、提交经验）、项目经理（处理与闭环、生成变更单草稿）、所有成员（登记、作废、查看） |
| 使用设备 | 现场手机为主，办公电脑查看台账 |

**场景 A：质检定责**：打开自动生成的不一致问题 → 选择原因 → 看到处置建议。
**场景 B：补签变更**：原因为「设计已改但未签变更单」→ 项目经理一键生成变更单草稿 → PAGE-F07-02。
**场景 C：手工登记**：任一成员发现问题 → 登记 → 对策或负责人可先空着。
**场景 D：闭环 / 重开 / 作废 / 沉淀经验**。

## 4. 信息架构
1. 顶栏：标题、演示身份、主操作「登记问题」（所有成员）
2. 问题台账卡：计数（未闭环 N、超期 N）；状态 chips；来源、等级、工段筛选；排序说明；列表；分页
3. 详情抽屉（右侧滑出，手机全屏）：头部（编号 · 来源、描述、状态印章）；闭环阻断提示；基本信息；不一致来源；原因与处置建议；补充对策与指派；留痕记录；底部操作
4. 弹窗：登记问题、作废问题、提交到公司经验库

## 5. 界面内容

### 5.1 台账

**筛选**：状态 chips「全部有效（不含已作废）/ 未闭环 / 处理中 / 已闭环 / 已作废」；来源（核对不一致 / 手工登记）；等级（严重 / 重要 / 一般）；工段（6 个工段）。已作废问题只在「已作废」中可见（AC-F08-07）。

**列表字段**

| 字段 | 内容 |
| :--- | :--- |
| 编号 | WT-nnn（DEC-084） |
| 问题 | 描述；下行「工段 · 楼层 · 房间」，对策为空时追加「待补充对策」 |
| 来源 | 「不一致 CK-xxx」或「手工登记」 |
| 等级 | 严重 / 重要 / 一般 |
| 负责人 | 姓名或「待指派」 |
| 要求闭环 | 日期 |
| 超期（天） | 今天 − 要求闭环日期，仅未闭环/处理中且已过期时显示（AC-F08-04） |
| 状态 | 印章：未闭环、处理中、已闭环、已作废 |

**排序**：未闭环与处理中在前，按超期天数从大到小；其次按要求闭环日期；已闭环、已作废在后（AC-F08-04）。

### 5.2 详情抽屉

**基本信息**：等级、所属工段、楼层 · 房间、负责人（空显示「待指派」）、要求闭环日期、超期天数、对策（空显示「待补充对策」）、闭环日期；已作废时加作废理由。

**不一致来源**（仅由核对不一致生成的问题，AC-F08-01）：检查点编号（链接 PAGE-F06-01）+ 最新核对结论、工作项、发现时点（覆盖前 / 后 + 时间）、照片缩略图。

**不一致原因（质检选择，AC-F08-02）** 与处置建议：

| 原因 | 处置建议 | 附带动作 |
| :--- | :--- | :--- |
| 设计已改但未签变更单 | 补签变更单（可一键生成变更单草稿） | 项目经理可见「一键生成变更单草稿」→ PAGE-F07-02（DEC-083）；已生成时显示变更单编号与状态 |
| 施工偏离签认图 | 返工后复核 | 指向检查点，由质检追加复核 |
| 图纸本身未表达清楚 | 设计经理出新版或书面澄清 | 指向图纸页 |

未选原因时提示「尚未选择原因。由质检选择后显示处置建议。」非质检角色原因只读。

**补充对策与指派**（项目经理、质检，DEC-082）：对策、负责人；保存后追加留痕。

**留痕记录**：每次生成、选原因、补对策、指派、闭环、重开、作废、提交经验都追加一条（操作 · 操作人（角色） · 时间）。

**底部操作**

| 按钮 | 可见角色 | 显示条件 |
| :--- | :--- | :--- |
| 标记已闭环 | 项目经理、质检 | 未闭环 / 处理中 |
| 重新打开 | 项目经理、质检 | 已闭环 |
| 提交到经验库 | 质检 | 已闭环且由不一致生成 |
| 作废 | 所有成员 | 未作废 |

### 5.3 登记问题弹窗（AC-F08-03）

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| 问题描述 | 是 | — |
| 等级 | 是 | 一般 / 重要 / 严重 |
| 所属工段 | 是 | 6 个工段 |
| 要求闭环日期 | 是 | — |
| 楼层 | 是 | 选楼层后加载房间 |
| 房间 | 是 | — |
| 对策 | 否 | 空时记为「待补充对策」 |
| 负责人 | 否 | 空时记为「待指派」 |

必填范围为 design-derived DEC-081。

### 5.4 作废弹窗（AC-F08-07）
说明「问题不能删除。作废后不可撤回，不计入问题统计，仍可在『已作废』筛选中查看。」+ 确认摘要（问题、当前状态、操作人）+ 作废理由（必填）+「确认作废」。

### 5.5 提交到经验库弹窗（AC-F09-01）
说明「已自动脱敏：只提交以下字段，不含业主姓名、项目地址和照片。提交后进入待审核，审核通过才对其他项目可见。」；摘要字段：工段、工序、问题类型、检查要点、对策；复选「另行附带现场照片（N 张）」默认不选；按钮「提交待审核」。

### 5.6 示例数据
WT-021 二楼书房 B 门洞净宽 860mm，与图纸 900mm 不符（CK-031，重要，超期 3 天，未选原因）；WT-019 一楼厨房烟道预留位偏移 120mm（CK-027，严重，已生成 BG-003）；WT-017 负一楼设备间砌体垂直度偏差 12mm（手工，处理中，超期 12 天）；WT-022 夹层楼梯间砂浆饱满度不足（待补充对策、待指派）；WT-015 一楼客厅门洞过梁搭接长度不足（已闭环，可提交经验库）；WT-016 已作废（与 WT-017 重复登记）。

## 6. 交互流程

### 6.1 加载
加载本项目问题，默认「全部有效」并按超期排序；带 `?id=` 时直接打开该问题抽屉。

### 6.2 核心流程
```
质检提交不一致核对（PAGE-F06-02）→ 自动生成问题：带检查点、工作项、楼层、房间、照片、发现时点，状态「未闭环」（AC-F08-01）
质检选原因 → 保存并留痕 → 显示对应处置建议（AC-F08-02）
标记已闭环
  ├─ 由不一致生成且检查点最新结论仍为「不一致」→ 拒绝：「请先由质检复核为一致或已变更」（AC-F08-06）
  └─ 否则 → 状态「已闭环」，闭环日期=当天，追加留痕（AC-F08-05）
重新打开 → 清除闭环日期，状态「处理中」，追加留痕（AC-F08-05）
作废 → 填理由 → 确认 → 状态「已作废」，保留记录（AC-F08-07）
提交到经验库 → 预览脱敏字段 → 提交 → 生成待审核条目（AC-F09-01）
登记问题 → 校验 → 保存为「未闭环」（AC-F08-03）
```

## 8. 业务规则与校验

### 8.1 状态流转
```
未闭环 ──闭环──→ 已闭环 ──重开──→ 处理中 ──闭环──→ 已闭环
任一未作废状态 ──作废（需理由）──→ 已作废
```

### 8.2 校验

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 登记必填 | 提交时 | DEC-081 的 6 项 | 字段旁提示，如「请填写问题描述」 |
| 作废理由 | 确认时 | 非空 | 「请填写作废理由」 |
| 不一致闭环 | 点闭环时 | 检查点最新结论须为一致或已变更 | 「请先由质检复核为一致或已变更」 |

### 8.3 设计补充
- **DEC-081**：手工登记时描述、等级、工段、楼层、房间、要求闭环日期必填；对策、负责人可空（AC-F08-03 只定义了空值记法）。
- **DEC-082**：项目经理、质检可在抽屉中补充对策和指派负责人，每次变化追加留痕（用于消除「待补充对策」「待指派」）。
- **DEC-083**：「一键生成变更单草稿」只对项目经理显示，与「仅项目经理发起变更单」（US-F07-01）一致；草稿编号规则见 PAGE-F07-02 的 DEC-071。
- **DEC-084**：问题编号显示为 WT-nnn（项目内序号）；状态印章：未闭环/处理中为橙、已闭环为绿、已作废为灰。
