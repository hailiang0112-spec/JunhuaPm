## 2. 页面概述

- **定位**：公司的「检查经验」沉淀处：质检把已闭环的不一致问题变成脱敏的检查要点和对策，审核后全公司可见，下次新建检查点时被推荐。
- **存在理由**：同样的偏差不在下一个工地或下一道工序重演（US-F09-01）。
- **不做什么**：
  - 不在本页新建条目：条目只能从已闭环的不一致问题提交（REQ-F09-01，入口在 PAGE-F08-01）。
  - 不显示业主姓名、项目地址和照片（AC-F09-01）；质检提交时另行选择附带的照片才显示。
  - 不删除条目或旧版本：修改生成新版本，旧版本保留可查（AC-F09-03）。

## 3. 用户与场景

| 角色 | 本页可做的事 |
| :--- | :--- |
| 质检 | 查看全部已审核条目；查看待审核队列；审核（选择状态）；修改已审核条目（生成新版本）；看版本历史 |
| 其他角色（业主、代理人、项目经理、设计经理、预算专员、公司管理员） | 查看已审核条目与版本历史（只读） |

- **场景 A 审核**：王工打开「待审核」→ 看到孙工提交的「砌墙 · 门洞砌筑」条目（已自动脱敏）→ 审核，选择「未验证经验」→ 确认摘要 → 条目对全公司可见，记录审核人和时间。
- **场景 B 升级状态**：同类问题在三个工地被复核验证 → 王工修改该条目状态为「已验证」并补充对策 → 生成 v3，v1、v2 保留。
- **场景 C 项目经理查阅**：张工开工前按「砌墙」筛选，看已验证的条目。

## 4. 信息架构

1. 外壳：工地切换器「全部工地」，导航「公司经验库」高亮。
2. 顶栏：标题「公司经验库」、副标题「全公司项目可见 · 已脱敏，不含业主姓名、项目地址和照片」。
3. 标签：经验条目 / 待审核（数字，仅质检可见，DEC-114）。
4. 筛选栏：工段 chips（全部 + 六个工段）、状态 chips（全部 / 已验证 / 历史观察 / 未验证经验）、关键词搜索。
5. 条目卡片列表（电脑两列，手机单列）+ 分页。
6. 审核弹窗、修改弹窗、版本历史弹窗。

## 5. 界面内容

**条目卡片**

| 元素 | 示例 |
| :--- | :--- |
| 工段 · 工序 | 色点 + 砌墙 · 门洞砌筑 |
| 状态印章 | 已验证（绿）/ 历史观察（蓝绿）/ 未验证经验（灰）；待审核（橙） |
| 问题类型 | 施工偏离签认图 / 设计已改但未签变更单 / 图纸本身未表达清楚（与 AC-F08-02 的原因一致） |
| 检查要点 | 砌筑前按签认版平面图复核门洞净宽，并预留两侧抹灰各 20mm；净宽偏差超过 10mm 判为不一致 |
| 对策 | 门洞两侧先立皮数杆并标注净宽，砌至 1.2m 时质检中间复核一次 |
| 照片 | 「附 1 张照片」（仅提交时选择附带才显示） |
| 版本与审核 | v3 · 王工审核 · 2026-10-20 14:12 |
| 操作 | 版本历史（所有人）；修改（质检） |

排序：已验证 → 历史观察 → 未验证经验，同状态按最近审核时间倒序。与新建检查点时的推荐顺序一致（AC-F09-04）。

**待审核条目（质检）**：同样的字段 + 「提交人 孙工 · 2026-10-26 18:40 · 来自已闭环的不一致问题」+「审核」按钮。

**审核弹窗**：条目全部内容（只读）+ 状态单选（未验证经验 / 历史观察 / 已验证，必选）→ 确认摘要（条目、选定状态、审核人、时间、「审核后对公司全部项目成员可见」）→ 审核通过。

**修改弹窗（质检）**：工序、问题类型、检查要点、对策、状态、修改说明（必填）→ 保存为新版本。

**版本历史弹窗**：倒序列出 v3（当前）/ v2 / v1：版本号、时间、操作人、状态、修改说明，可展开查看该版本的检查要点与对策。

## 6. 交互流程

```
打开 → 「经验条目」标签，默认全部工段、全部状态
点工段 / 状态 chip → 过滤；搜索按工序、检查要点、对策匹配

质检 → 「待审核」→ 审核 → 选状态 → 确认摘要 → 审核通过
     → 条目移入「经验条目」，印章盖章动效，提示「已审核，全公司项目可见」（AC-F09-02）

质检 → 修改 → 保存 → 生成新版本，版本号 +1，旧版本保留（AC-F09-03）→ 提示「已保存为 v4」

任何人 → 版本历史 → 查看各版本
```

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 正常态 | 有已审核条目 | 卡片列表 |
| 加载态 | 读取 | 卡片骨架屏 |
| 空状态 | 公司还没有已审核条目 | 「还没有经验条目。质检可在问题页把已闭环的不一致问题提交到经验库。」 |
| 筛选无结果 | 筛选无匹配 | 「没有符合条件的条目」+ 清除筛选 |
| 待审核为空 | 队列为空 | 「没有待审核的条目」 |
| 错误态 | 读取失败 | 「经验库加载失败（网络中断），请重试」+ 重试 |

- 无权限：经验库是公司级、已脱敏内容，公司内所有成员可看（PRD §3.2.1），不存在越权查看；审核和修改按钮只对质检显示，服务端同样校验（NFR-003）。
- 两名质检同时审核同一条目：先提交的生效，后提交的提示「该条目已由 王工 审核」。

## 8. 业务规则

- 提交时自动脱敏：条目只包含工段、工序、问题类型、检查要点和对策，不含业主姓名、项目地址和照片；质检可另行选择附带照片（AC-F09-01）。
- 公司内任一质检审核通过并选择状态后，条目对公司全部项目的成员可见，记录审核人、时间和状态（AC-F09-02）。
- 修改已审核条目的内容或状态生成新版本，旧版本保留可查（AC-F09-03）。
- 推荐顺序：已验证、历史观察、未验证经验（AC-F09-04）；推荐与「加入检查点」动作在 PAGE-F05-01 完成，本页列表使用相同排序。
- **DEC-114（design-derived）**：待审核队列只对质检显示（审核前条目不应对其他项目可见）；修改时内容与状态一起保存为一个新版本，并要求填写修改说明。
- **DEC-117（design-derived）**：外壳约定把「公司」分组设为仅公司管理员可见，而蓝图 §2 规定经验库公司内所有角色可看。本设计中「公司经验库」导航项对所有角色显示，「项目管理」「公司模板」仍仅公司管理员可见。

## 10. 数据需求

| 数据 | 方向 | 用途 |
| :--- | :--- | :--- |
| 已审核条目（当前版本）：工段、工序、问题类型、检查要点、对策、状态、版本号、审核人、时间、附带照片数 | 读取 | 列表 |
| 待审核条目、提交人、提交时间 | 读取 | 队列（质检） |
| 条目全部版本 | 读取 | 版本历史 |
| 审核结论（状态）、修改内容与修改说明 | 提交 | 审核 / 新版本 |

明确排除：业主姓名、项目地址、问题原始照片（未选择附带时）。
