## 2. 页面概述

### 2.1 一句话定位
一个工段的施工全貌：进度、工作项、出勤、验收图片、问题与计划变更，同一模板服务六个工段。

### 2.2 存在理由
1. 项目经理每天在这里登记出勤、看工作项进度；没有它就回到微信群和纸面。
2. 「不得覆盖」必须在工段页醒目显示，防止未放行先覆盖（AC-F06-11）。
3. 计划调整必须自动留档，否则延期无从追溯（AC-F14-01）。

### 2.3 不做什么
- 不在本页编辑工作项基线与资料（PAGE-F05-01）；不新增工作项（PAGE-F03-02）。
- 问题的闭环、重开、作废在 PAGE-F08-01 处理，本页问题卡只读并提供入口（DEC-301）。
- 工段状态不允许手工修改（AC-F03-06）。

## 3. 用户与场景
| 维度 | 描述 |
| :--- | :--- |
| 角色 | 项目经理（主要，登记出勤、编辑计划）；质检、设计经理、业主查看与上传验收图片 |
| 使用设备 | 电脑与手机 |

**场景 A：每日收工登记出勤**：项目经理点「登记出勤」→ 日期默认今天 → 填 6 人 → 保存后累计人工日、日均、峰值重算（AC-F11-01）。
**场景 B：补登一周**：节后点「批量登记出勤」→ 选 10-19 ~ 10-27、6 人、仅工作日 → 预览「将写入 8 天」→ 写入（AC-F11-02）。
**场景 C：顺延工段**：书房 B 门洞待变更，项目经理把砌墙结束日从 10-18 改到 11-08，填原因 → 自动追加留档，工期 +21 天（AC-F14-01）。

## 5. 界面内容

### 5.1 KPI 六卡（AC-F10-10、AC-F03-05、AC-F03-06）
| 卡片 | 内容 |
| :--- | :--- |
| 工段进度 | Σ(wi×pi)÷Σwi，1 位小数；无工作项为 0%；计划基准 =（今天−计划开始）÷（计划结束−计划开始），显示领先/滞后百分点 |
| 计划开始 / 实际开始 | 计划开始日；实际开始 = 首个出勤 > 0 的日期，无则「未进场」 |
| 计划结束 / 实际结束 | 计划结束日；「至 10-27 在施」或「完工 MM-DD」 |
| 工期 / 已施工天数 | 计划工期（含首尾）；实际施工天数 |
| 出勤 · 峰值 | 峰值人数；累计人·日；未登记天数 |
| 工作项 / 问题 | 已完成 / 总数；状态「未开始 / 进行中 / 已完成（自动）」——进度 0、0 < 进度 < 99.95、≥ 99.95；问题数与闭环数 |

示例（砌墙）：35.2%，计划基准 76.0%，滞后 40.8 个百分点；8/31 项；进行中（自动）。

### 5.2 计划变更留档（AC-F14-01、AC-F14-02）
列：记录时间、变更项、变更前 → 变更后、工期影响（天）、原因备注；头部「累计 N 次变更」「工期较初始延后 N 天」。只追加，不可编辑删除。无记录时显示说明。

### 5.3 工作项表（AC-F10-10、AC-F06-11）
- 筛选：楼层 chips（全部 + 本工段涉及的楼层 + 全楼通用）；选中楼层后出现房间 chips（不限 + 该楼层涉及的房间）。有筛选时显示「已按楼层「二楼」+ 房间「书房 B」筛选，本工段 1 / 31 项｜清除筛选」。
- 列：序号、工作项（→ PAGE-F05-01）、工作说明与验收标准（验收标准以「验收」小块附在说明下）、楼层 / 房间、计划日期（逾期未完成标红）、实际完成日期（滞后标签）、负责人、权重、完成度条、状态标签、检查点、资料数（→ 工作项资料）。
- 检查点列每行最多 1 个印章（DEC-304）：有未放行隐蔽检查点 →「不得覆盖」（红，优先级最高）；最新核对不一致 →「不一致」（红）；检查点全部放行 →「已放行」（绿）；无检查点「—」。点印章 → PAGE-F06-02。
- 表下汇总：当前筛选范围加权完成度、工段加权完成度及公式、「不得覆盖」含义说明。
- 分页每页 20 条。

### 5.4 本工段楼层 · 房间分布
每个涉及的楼层一块：楼层名（点击筛选上表）、事项数、楼层加权完成度与进度条、各房间 chip（名称 + 完成度，点击筛选该房间并滚动到工作项表）。

### 5.5 出勤（AC-F11-01 ~ AC-F11-03）
- 柱图：工段工期内每天一格，柱为当日登记人数；过去日期无登记画虚线框「未登记（按 0 计）」；红色虚线为今天；工段未开始时显示「工段尚未开始，YYYY-MM-DD 起可登记出勤」。
- 统计：累计人工日、日均出勤（累计 ÷ 施工天数）、峰值、施工天数、未登记天数。
- 台账：工期内截至今天的每一天，倒序；列日期、星期、人数（无登记显示「未登记」）、来源（手工登记 / 原型导入）、登记或修改按钮。

### 5.6 验收图片（AC-F12-04）
- 头部计数：已验收、待复验、施工中。
- 图片卡：缩略图、状态印章（已验收绿 / 待复验橙 / 施工中灰）、说明、楼层房间、上传人与日期、来源「原型导入」（如有）、「切换为「下一状态」」按钮（施工中 → 待复验 → 已验收 → 施工中，DEC-307）。
- 上传卡：选择图片，支持多张，新上传默认「待复验」。

### 5.7 问题卡
- 状态 chips：全部 / 未闭环 / 处理中 / 已闭环（带数量）；「登记问题」→ PAGE-F08-01 预填本工段。
- 卡片：编号、描述、等级、状态印章、楼层·房间、超期天数、「查看与处理」；发现日期、负责人、要求闭环、实际闭环、闭环耗时或已挂起天数、来源（检查点 CK-031 / 手工登记 / 原型导入）；对策。
- 排序：超期天数从大到小。

### 5.8 编辑工段计划弹窗（AC-F14-01 ~ AC-F14-03）
| 字段 | 必填 | 规则 |
| :--- | :--- | :--- |
| 计划开始日期 | 是 | 不能晚于结束日期 |
| 计划结束日期 | 是 | — |
| 班组负责人 | 否 | 文本 |
| 工段权重 | 否 | 正整数 |
| 施工范围 | 否 | 文本 |
| 原因备注 | 否 | 写入留档 |

弹窗下方实时预览「保存后将追加 1 条留档（不可修改）」及每个变化字段的前后值、工期影响天数（DEC-305）。

### 5.9 登记出勤弹窗（AC-F11-01）
日期（限本工段工期内，默认今天）、出勤人数（0–40 整数）。已有登记的日期打开时带出原值。

### 5.10 批量登记出勤弹窗（AC-F11-02）
开始日期、结束日期（均限工期内）、每天人数（0–40）、写入范围单选：每天 / 仅工作日（跳过周日）/ 仅至今日。下方预览「将写入 N 天（起 ~ 止），其中 M 天已有登记将被覆盖为新人数」（DEC-306）。

## 6. 交互流程

```
保存工段计划
  ├─ 开始 > 结束 → 字段提示「开始日期不能晚于结束日期」，不保存（AC-F14-03）
  ├─ 无字段变化 → 关闭，提示「计划未变化，未生成留档记录」（AC-F14-02）
  └─ 有变化 → 保存，留档表顶部追加一条（时间、工段、变化字段前后值、工期增减天数、原因），KPI 重算（AC-F14-01）

登记出勤 → 日期不在工期内 / 人数不在 0–40 → 字段错误
         → 通过 → 保存，KPI、柱图、台账重算，提示「10-27 出勤 6 人已保存」
批量登记 → 校验同上，范围内无可写日期时提示 → 通过 → 按范围逐日写入，提示「已写入 N 天，每天 X 人」
上传验收图片 → 新图片状态「待复验」；点切换按钮 → 状态推进
切换工段 chip / 左侧导航 → 同模板加载对应工段（DEC-314）
```

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 加载 | 进入或切换工段 | KPI、表格、图表骨架屏 |
| 未开工 | 今天早于计划开始 | 进度 0%、未开始（自动）；出勤图显示开始日期说明；图片区只有上传卡与说明；问题区「本工段暂无问题记录…」 |
| 筛选为空 | 楼层 / 房间无事项 | 表内「该筛选条件下本工段暂无工作项。项目经理可在项目结构中新增并指定楼层与房间。」 |
| 提交中 | 保存弹窗 | 主按钮禁用防重复提交 |
| 错误 | 加载或保存失败 | 说明原因，弹窗内容保留可重试 |
| 无权限 | 非项目成员 | PAGE-F01-03 |
| 工段不存在 | `phase` 参数无效 | 回到第一个工段 |
