## 2. 页面概述

### 2.1 一句话定位
项目各方在同一处留言沟通，按身份分板块，所有留言留痕。

### 2.2 存在理由
1. 微信群消息被刷掉、无法追溯（US-F13-02）。
2. 留言人必须取登录账号，不能冒名。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 归属正确 | 100% 留言按发布者角色进入对应板块 |
| 留痕 | 删除后仍保留占位与删除记录 |

### 2.4 不做什么
- 不能删除他人留言（AC-F13-04）。
- 不能编辑已发布留言。
- 不提供「清空板块」——原型功能已退役（PRD §3.2.1）。

## 3. 用户与场景

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 全部项目成员 |
| 使用设备 | 手机为主 |

**场景 A：业主发布**：写下需求 → 发布 → 进入「业主」板块。
**场景 B：工地经理回复**：在业主留言下回复 → 回复按时间正序挂在原留言下。
**场景 C：删除自己的留言**：确认后显示「该留言已删除」。

## 4. 信息架构
1. 顶栏：标题、演示身份
2. 发布留言卡：输入框 + 归属提示「将以 {姓名（角色）} 的身份发布到『{板块}』板块（按角色自动归入）」+ 发布
3. 板块区：电脑端三列（业主 / 工地经理 / 设计师）；平板与手机为板块切换 chips + 单列

## 5. 界面内容

### 5.1 板块归属（AC-F13-03）

| 发布者角色 | 板块 |
| :--- | :--- |
| 业主 | 业主 |
| 设计经理 | 设计师 |
| 项目经理及其他角色（质检、预算专员、公司管理员、业主代理人） | 工地经理 |

### 5.2 留言条目
- 头像字、留言人姓名（取登录账号）、角色、时间
- 内容；已删除时显示「该留言已删除」+「删除记录：{删除人} · {时间}」
- 操作：回复（主留言）、删除（仅本人且未删除）
- 回复区：缩进挂在原留言下，按时间正序；回复同样可由本人删除
- 板块头显示条数

排序：主留言按时间倒序（AC-F13-03），回复按时间正序（AC-F13-04）。

### 5.3 示例数据
业主板块：刘先生「三楼露台想加一个户外洗手池……」（张工、李工回复）；刘先生 2026-10-20 的留言已删除。工地经理板块：张工「今天砌墙班组 6 人进场……」、王工、赵会计、刘太太（业主代理人）的留言。设计师板块：李工「二楼平面布局图 V4 已发布……」。

## 6. 交互流程
```
发布 → 内容为空：「请填写留言内容」
     → 有内容：以登录账号姓名发布，归入角色板块，出现在该板块最上方（手机端自动切到该板块）
回复 → 展开回复框 → 提交 → 挂在原留言下（正序）
删除（本人）→ 确认摘要（留言摘要、发布时间、删除后表现）→ 显示「该留言已删除」并保留删除记录
```

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 正常 | — | 三个板块 |
| 空板块 | 板块无留言 | 「还没有留言」+「{板块}板块的留言会显示在这里。」 |
| 加载 | 请求中 | 骨架屏 |
| 错误 | 网络中断 | 「公告栏加载失败（网络中断）」+ 重新加载 |
| 无权限 | 访问未受邀项目 | 跳转 PAGE-F01-03 |

| 边界 | 处理 |
| :--- | :--- |
| 他人留言 | 不显示删除按钮 |
| 已删除留言 | 不能再回复；已有回复保留 |
| 内容上限 | 500 字 |

## 8. 业务规则
- 留言人取登录账号姓名，不可自填（AC-F13-03）。
- 只能删除自己的留言，删除保留记录（AC-F13-04）。
- **DEC-133（design-derived）**：一人在本项目兼多个角色时，按「业主 > 设计经理 > 其他」的优先级确定板块。
- **DEC-134（design-derived）**：删除留言前弹出确认摘要（删除不可恢复）。

## 9. 页面流转
导航「公告栏」──→ 本页（发布、回复、删除均在本页完成）
