## 2. 页面概述

- **定位**：登录后第一眼看到「现在该我处理什么」，并能一键把催办消息发到微信。
- **存在理由**：成员不再靠翻微信群找事（US-F16-01）；放行超时和未放行先覆盖要第一时间被业主看到（AC-F06-13、AC-F06-12）。
- **不做什么**：
  - 不在本页直接签认或放行：签认、放行都要先看完整内容，跳转到对应页面处理。
  - 不做短信或企业微信推送（PRD「明确不做」），催办靠复制微信消息。
  - 不做自动放行：超时只置顶提醒（AC-F06-13）。

## 3. 用户与场景

| 角色 | 本页看到的待办类型（AC-F16-01） |
| :--- | :--- |
| 业主 | 待签基线、待签图纸、待签变更单、待放行检查点；另含超时（AC-F06-13）、未放行先覆盖（AC-F06-12）、即将施工基线未签认（AC-F05-09）、新增检查点知会（AC-F06-16） |
| 业主代理人 | 待放行检查点（含超时） |
| 业主方成员 | 无待办（只读，AC-F01-12）；被业主指定为代理人后按「业主代理人」出现待放行检查点。空状态说明这一点 |
| 质检 | 待核对检查点 |
| 预算专员 | 待预算定价变更单 |
| 设计经理 | 待出新版图纸 |
| 项目经理 | 被退回基线、被驳回变更单（去处理 → PAGE-F07-02「修改后重新提交」，AC-F07-09）、即将施工基线未签认；另含超时检查点（AC-F06-13） |
| 公司管理员 | 对项目业务数据只读，不承担签认、核对、放行、定价待办（AC-F01-13）→ 待办区为空状态并说明原因；我的工地显示公司全部项目 |

一人兼多个角色时，各角色的待办合并显示，不重复。

- **场景 A 业主早上打开**：置顶的红色「超时」印章提示 CK-018 夹层设备间隔墙拉结筋已超时 18 小时 → 点「去处理」进入放行页。
- **场景 B 项目经理催办**：对「BG-003 待业主签认」点「复制微信消息」→ 粘贴到业主微信群。
- **场景 C 多工地**：质检王工同时在两个工地，待办按项目名区分，我的工地显示两张卡片。

## 4. 信息架构

1. 外壳：左侧导航（「我的待办」高亮，带待办总数红点）/ 手机底部标签「待办」带红点；工地切换器显示「全部工地」。
2. 顶栏：标题「我的待办」、副标题（日期、待办总数、超时数）、刷新时间。
3. 主区左栏：类型筛选 chips → 「超时与需立即关注」置顶分组 → 其余待办按类型分组。
4. 主区右栏（手机在待办之后）：我的工地卡片。

## 6. 交互流程

```
打开首页（登录后 / 导航）
  → 读取当前账号在全部项目中各角色的待办 → 超时置顶 → 渲染
  → 每 60 秒自动刷新一次（蓝图 §7），顶栏显示「更新于 10:20」

点类型 chip → 只看该类型（「全部」恢复）
点「去处理」→ 跳转处理页；处理完成后返回，该待办消失、导航数字减少（AC-F16-02）
点「复制微信消息」→ 文本写入剪贴板 → 顶部提示「已复制」（AC-F16-03）
点我的工地卡片 → 进入该工地 PAGE-F10-01 项目总览
```

- **DEC-115（design-derived）排序**：超时与「未放行先覆盖」放在顶部「需立即关注」分组，超时按超时时长倒序；其余按类型分组，组内按截止时间升序。
- **DEC-118（design-derived）知会待办的消失方式**：AC-F06-16 只要求「生成知会待办」，没有规定何时消失。知会不需要业主做业务操作，所以提供「知道了」按钮，由本人确认后从自己的待办中移除（多名业主各自确认，互不影响）；「查看」进入工作项详情。
- **DEC-116（design-derived）消息格式**（AC-F16-03 规定了必须包含的内容，格式为设计补充）：

```
【君华新城 · 联排别墅装修工程】待放行检查点
事项：CK-018 夹层 · 设备间 隔墙拉结筋
负责人：刘先生（业主）、刘太太（代理人）
已超时 18 小时（放行时限 24 小时），请尽快处理
直达链接：https://<平台域名>/p/junhua-xincheng/checkpoints/CK-018
```

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 正常态 | 有待办 | 置顶分组 + 类型分组 + 我的工地 |
| 加载态 | 首次读取 | 待办列表与工地卡片骨架屏 |
| 空状态 | 没有待办（如公司管理员） | 「当前没有需要你处理的事项」；我的工地照常显示 |
| 无工地 | 账号没有任何项目角色（被全部移除） | 我的工地区：「你还没有加入任何工地，请联系项目经理或公司管理员发送邀请」 |
| 错误态 | 读取失败 | 「待办加载失败（网络中断），请重试」+ 重试按钮 |
| 复制失败 | 浏览器拒绝剪贴板 | 弹出消息文本框，提示「请长按全选后复制」 |

- 无权限：本页只展示本人数据，不存在越权；某工地被移除后其待办和卡片在下一次刷新时消失（AC-F01-06）。
- 多名业主：一名业主签认或放行后，另一名业主的同一待办在刷新后消失（AC-F01-10，由处理页保证）。

## 8. 业务规则

- 待办类型与角色的对应关系严格按 AC-F16-01，见第 3 节。
- 「超时」：检查点进入待放行后超过项目放行时限（默认 24 小时，可设 1–72 小时）仍未放行，在业主、业主代理人和项目经理的待办中标「超时」并置顶；检查点仍保持未放行（AC-F06-13）。
- 「未放行先覆盖」：业主待办中显示该事件（检查点、时间、记录人）（AC-F06-12）。
- 「即将施工，基线未签认」：工作项计划完成日期距今 ≤ 7 天且基线未签认，向项目经理和业主生成（AC-F05-09）。
- 导航上的数字 = 当前列表待办总数（AC-F16-01），处理后同步减少（AC-F16-02）。
