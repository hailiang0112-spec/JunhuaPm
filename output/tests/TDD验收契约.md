# TDD 验收契约 · 君华装修项目管理平台

> 给 Coding Agent：这份文件定义本次开发的整体验收完成条件。读取同目录上游产物后持续实现、验证、修复和必要回归；有可操作版本就立即给用户入口试用，并说明 Agent 仍在测试和修正。用户叫停立即停止；外部条件不足时保留未验证项并说明停点。全部 required 通过后才能宣称整体验收完成，不把提前试用或停止执行记为验收通过。

> 初始数据可准备必要前置条件，但不得预先完成待验动作；期望值以已确认规则或已知业务例子为依据，不由被测计算或照抄其实现生成。验收结论限于实际执行的起点、动作和终点。

> **执行门禁（严禁跳过）**：完整 `/goal` 在改任何代码前，必须提取本文件全部验收 ID，建立或沿用 `output/tests/TDD验收结果.md`；无结果台账时全量置为 `pending`；已有台账按本轮来源、断言、实现、依赖和环境核对影响，保留仍充分有效的证据，新增、失效或存疑项置 `pending`。可用证明同一结果的直接方法替换自选“验证方式”，不得改变通过标准、适用环境或用户指定形式；记录实际动作与证据，真实执行且满足整行标准才记 `pass`；候选阶段补齐缺口与必要集成验收。复用保留原记录或引用原结果，不冒充本轮执行，不逐行补写复用论证。未建台账先写代码、未真实执行便凭推测倒填、用已失效日志标 `pass`，均视为 TDD 没有执行。

> 结果文件元信息固定写成 `- contract_sha256: sha256:<64位hex>` 与 `- run_started_at: <ISO 8601>`，表头为 `TDD ID | 状态 | 实际验证动作 | 证据`。功能项保留真实命令及退出码、API 结果或测试结果；`DESIGN-*` 保留 `actual=tests/visual/实际截图.png; reviewer=independent-visual; review=pass; blocking=0`。图片使用 `tests/visual/` 下有效 PNG 的相对路径；actual 必须来自真实运行成品，动作如实说明已看图及核对的 PAGE、状态和设计锚点，不要求固定措辞；不能用自造渲染器冒充原生运行效果。契约行明确要求“截图对”或“严格对照”时，还需真实原型 baseline PNG，双图路径不同、尺寸相同、数据与状态一致，并实际查看两张图片；主动提供的 baseline 也须真实有效且路径不同。文件名无需含 PAGE ID，独立验收官核实内容归属。详细证据规则可定位已安装 tdd-master 的《TDD验收契约规范》§7，不能因未安装而省略上述要求。

> 完成前必须用 tdd-master 校验器的 `--result` 模式或等价脚本机械核对契约与结果；严禁人工目测后宣布全绿。
