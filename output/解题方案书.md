# 君华别墅装修项目管理平台 解题方案书

> 一句话解法：用「签认版图纸 + 检查点对图照片 + 变更单」这条证据链，把「开工前基线签认、图纸版本管控、盖住前对图检查、不一致处置规则」四个杠杆和「不一致在被下一道工序覆盖前发现的比例」连起来，以放行关口加条件提醒的形式，帮业主在开工前和工序完工时做出签认、放行、定责的决定，并用水电阶段的前后对比证明有效。

## 1. 要改进的决策
- **决策人**：业主（核心使用者）。参与方有项目经理、设计经理、公司质检、预算专员。
- **决策时刻**：
  - **开工前（为主）**：逐项签认工作基线，包括按哪一版图纸、什么做法、多少费用、什么施工顺序、谁来质检、证据放在哪里。
  - **完工时**：凭质检证据对照图纸放行。如果不一致，判定是设计变更（补签变更单，确定费用由谁出）还是施工偏差（返工）。
- **频率**：每项工作开工前和完工时各一次。全屋共 187 项工作，分布在 6 个工段。
- **现在怎么做**：
  - 图纸改了约十版，以 CAD/PDF 发在微信里，各版没有改动说明，业主只在最终版签字。
  - 工人拿的是新图，但现场会做施工调整，调整只是口头约定加微信里一句话。
  - 质检照片存在公司内部小程序里，项目资料都在微信群。
  - 不一致由项目经理反馈，业主只能被动接受。
- **做错一次的代价（用户估算）**：一套房会出现几十次图纸和现场不一致，其中有结构施工错误。这类错误通常交房后才发现，无法挽回，最后只能妥协接受，损失难以估算。

## 2. 解题图（控制回路）

```text
[可控] ① 开工前基线签认      ② 图纸版本管控 + 变更单
       ③ 盖住前对图检查点    ④ 不一致处置规则
  → [过程] 盖住前检查按时完成率 ↑ / 施工用图为最新签认版的比例 ↑ / 变更先签后做的比例 ↑
  → [结果] 不一致在被下一道工序覆盖前发现的比例（越高越好）
外部环境：业主自身改主意、设计深化不足（已改十版）、原始结构条件
回流：检查点结果 + 不一致案例 → 检查经验库（质检审核）→ 成为下一道工序的检查重点
```

## 3. 题型与先例
- **主题型**：诊断，用经验规则 / 专家清单核对，加流程留证（解法阶梯第 0–1 级）。
- **副题型**：能力复制。把不一致案例沉淀为后续工序的检查重点。
- **先例**（详见 `solution/evidence/先例.md`、`方法.md`）：
  - **京津冀家装示范合同（2023）**：施工图双方签字；变更以签字的变更单为准，甲方不得私下和设计师或工人约定变更；隐蔽验收合格才能进入下道工序，擅自施工的后果由擅自方承担；竣工时交付竣工图和影像资料。https://scjgj.beijing.gov.cn/bsfw/bmfw/sfwbbm/jjjht/202312/P020231205615140227980.doc
  - **实测实量**只能证明「做得好不好」，证明不了「做得对不对」。T/CBDA 19-2018 只规定允许偏差。https://www.gongbiaoku.com/mobile/book/gl119543nkv
  - **证明与图纸不符**，海外工具的共同做法是三样东西：签认版图纸、钉在图纸位置上的照片、图纸版本比对。可参考 PlanRadar（https://planradar.com/product/photo-documentation/ ）、Fieldwire（https://fieldwire.com/blueprint-app ）、Autodesk Construction Cloud（https://construction.autodesk.co.uk/tools/construction-drawing-management ）。
  - **国内平台的透明主要落在资金上**：贝壳被窝、齐家网都是「节点验收 + 业主确认 → 放款」。齐家网的失败案例出在合同与三方协议金额不一致，说明全过程只能有一份签认的合同、清单和图纸，这是所有机制的前提。https://www.bbtnews.com.cn/2021/0529/397811.shtml
  - **增项是家装投诉的头号来源之一**，法院按书面合意判决。上海 2019 年抽样中，增项占 23.72%，质量占 36.5%。https://www.shzsxh.cn/article/detail?id=313 ；https://www.huichenglawyer.com/pufaku/76249.html
  - **别墅专用标准** T/CDZS 005—2024《别墅及大宅全装饰装修工程交付规范》：https://www.ttbz.org.cn/Home/PdfFileStreamGet/c3QsMTIwNTQ3 （直接抓取返回 404，现行状态待复核）。同行的做法是进场前完成专业接口深化：https://news.sina.cn/sx/2026-09-30/detail-initpatt7641669.d.html
  - **「与设计 / 图纸不符」在公开投诉统计中没有单独占比**：未找到公开资料。
- **前身项目与教训**：原型 v1.20（`input/原型-v1.20.html`）已有阶段 × 楼层 × 房间的工作项、问题台账、出勤和资料库，但缺图纸版本、签认、变更单和对图检查点，数据只存在单机浏览器里。原型中记录的真实问题（二楼书房 B 门洞净宽 860mm 与图纸 900mm 不符；一楼厨房烟道偏移 120mm）正好属于本题。

## 4. 数据现实
- **对象（一行代表什么）**：一个检查点，即「房间 × 工作项 × 签认图纸版本 × 图纸位置」，在被盖住前核对一次。结果为一致、不一致或已变更，并记录发现时点。
- **关联键**：工作项编号 + 图纸版本号。变更单引用受影响的工作项和新图纸版本。
- **样本量 / 时间跨度 / 回流周期**：
  - 历史结构化样本 n = 0。
  - 微信群和十版图纸可以人工追溯少量历史不一致。
  - 前瞻采集覆盖剩余工期。回流周期为每个隐蔽工序覆盖前，当前在砌墙阶段，第一个关键窗口是水电（尚未开始）。
- **事前可知**：签认基线、图纸版本、检查人都是事前可知；发现时点和结果是事后结果，不作为预测特征。
- **缺口与补救**：
  - 逐版改动说明：由设计经理补写。
  - 变更单：从现在起采用书面变更单。
  - 对图照片：按新流程由质检采集。
  - 历史基线：通过数据小试整理。
- **数据小试结论**：待小试。这是最小切口的第一步。

## 5. 解法路线

| 路线 | 方法（阶梯级别） | 数据要求 | 输出形态 | 风险 |
|---|---|---|---|---|
| **A. 规则 + 证据链** | 第 0–1 级：检查点清单、节点核对、统计 | 签认图纸、检查点清单、对图照片、变更单 | 放行关口 + 条件提醒 + 结果统计 | 各方不配合，检查流于形式 |
| B. A + AI 辅助识别变更 | 第 0–1 级，加 LLM 判定「这句聊天是否构成变更」 | 加上微信聊天导出 | 同 A，另加漏签变更提醒 | 微信数据拿不到；AI 误判引发新扯皮 |
| C. 独立监理把关 | 人工巡检 + 台账 | 监理检查记录 | 监理报告 | 费用高，经验带不走，监理和施工方也会扯皮 |

> 选定：路线 A。
> - **理由**：病根是没有签认基线、变更靠口头、发现太晚，规则加证据链就能解决；可以在原型 v1.20 的工作项和房间结构上补齐。
> - **放弃了**：B 的自动识别漏签变更（等积累真实变更记录后再评估）、C 的第三方监理。
> - **代价**：开工前要列检查点清单，并需要公司按分工配合。

- **AI / LLM 用在哪一步**：第一版不用。后续可以评估两处：照片对图自动识别偏差、从聊天中识别漏签变更。前提是已经积累了签认图和标注好的样本。
- **输出形态**：放行关口 + 条件提醒，只提醒，不自动处罚。条件化规则示例：
  - 「当检查点在覆盖前没有签认版图纸、对图照片或业主放行，标记为**不得覆盖**，并提醒质检和项目经理；依据为示范合同的隐蔽验收条款；状态为未验证经验。」
  - 「当设计经理发布新版图纸，提醒受影响的工作项重新签认基线，未重签的工作项按旧版施工即视为风险。」
  - 「当核对结果为不一致：如有对应的已签变更单，结果记为已变更；如果是设计原因但没有变更单，提示补签变更单并由预算专员定价；如果是施工偏离签认图，提示返工。」
- **策略库**：要做「检查经验库」。
  - 内容：不一致案例按工序归类，转为后续工序的检查重点。
  - 状态分三种：未验证经验、历史观察、已验证。
  - 由公司质检审核入库，业主可以查看；每次修改都出新版本，并按版本追踪实际结果。

## 6. 怎么证明有效
- **成功标准**：
  - **基线**：历史上的不一致基本都在交房后才发现（用户陈述，用数据小试从微信群追溯核实）。
  - **目标**：到水电封墙完成时，同时满足三项：
    1. 隐蔽检查点 100% 在覆盖前具备签认版图纸、对图照片和业主放行；
    2. 水电阶段的不一致 ≥ 90% 在覆盖前发现；
    3. 变更 100% 先签后做。
  - **时间窗**：水电阶段，以水电封墙完成为准。
- **验证方法**：前后对比，即水电阶段的统计对比追溯出的历史基线。局限是只有单一工地、没有对照组，因此只能说明「发现时点前移了」，不能证明「不一致的次数减少了」。
- **事前验尸**：

| 失败原因 | 早期信号 | 应对 |
|---|---|---|
| 1. 公司或项目经理不配合，检查流于形式 | 照片在覆盖后补拍；没放行就已经封墙 | 把配合要求写进合同或补充协议；砌墙阶段先试 |
| 2. 检查点清单不全或太粗 | 覆盖后才发现的不一致中，「清单外」的占比 | 用历史不一致清单检验覆盖面；靠经验库持续补充 |
| 3. 照片没有证明力（没有标尺、位置、角度） | 发生争议时，照片被对方质疑的次数 | 规定拍照要求：钉在图纸位置、带尺寸参照、带时间 |
| 4. 现场口头调整绕过变更单 | 结果为「已变更」但找不到变更单的次数 | 没有签认变更单的调整一律按施工偏差处理 |
| 5. 业主看不懂图，放行卡住或沦为走过场 | 放行等待时长；放行时没有质检结论 | 放行前先由质检给出结论，业主只签字确认 |

## 7. 最小切口
- **范围**：
  - 场景：从现在的砌墙阶段开始，练顺「对图检查 → 放行」流程；水电阶段全楼执行。
  - 指标：覆盖前发现比例。
  - 数据：当前签认版图纸。
  - 只给建议，不自动处罚。
- **第一步**：
  1. **数据小试（现在）**：业主提供微信群记录和十版图纸，设计经理补写各版改动说明。AI 整理出「历史不一致清单」，标明位置、版本、发现时点、处理结果，附 n 和局限，用来核实基线，并检验检查点清单能不能覆盖历史问题。
  2. **砌墙练手（现在）**：列出砌墙检查点，例如门洞尺寸、烟道位置、管道井、过梁位置。每个点绑定签认图纸版本和位置，由质检对图拍照、业主放行；首批变更改用书面变更单。
  3. **水电进场前**：列出水电检查点清单（点位、管线走向、防水节点），由设计经理和质检确认后，业主签认基线；配合要求写进补充协议。
  4. **水电施工中**：执行盖住前对图检查和业主放行，按第 6 节目标统计；不一致案例由质检审核后入经验库。

## 8. 假设与未决
| ID | 假设 | 依据 | 风险 | 验证方法 |
|---|---|---|---|---|
| A1 | 一套房有几十次图纸与现场不一致，且有不可逆的结构性错误 | 用户估算 | 基线高估或低估，影响成功判断 | 数据小试：从微信群和十版图纸追溯 |

## 9. 留给 PRD 的问题
- 原型 v1.20 现有功能如何取舍：总览、楼层 / 房间矩阵、出勤日历、资料库、公告栏、Excel 导入等，哪些服务于本题，哪些后置。
- 数据从单机浏览器存储改为五方在线协作：账号、角色和权限，谁能签认、放行、审核入库。
- 图纸版本管理与「照片钉在图纸位置」的具体交互，以及手机现场使用的流程。
- 电子签认的形式与证据效力（参见《电子签名法》、法大大等电子签服务）。
- 放行关口是否与付款节点挂钩（参照被窝、齐家的资金托管模式），以及挂钩的时机。
- 补充事项、增项变更与费用台账如何与变更单统一。
- 数据导出与留档：发生争议时能拿出的证据包格式。
