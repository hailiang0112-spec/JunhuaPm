# 设计决策蓝图

> 上游：requirements.md（revision 1，scope = 全量交付）、PRD详细版.md、requirements-analysis.md（P0/P1 = 0）。本蓝图中的业务决定全部继承 D-1 至 D-12；设计层决定来自 2026-10-27 设计对齐的 4 个问题（用户都选了推荐项）。

## 1 盘子
- **scope**：全量交付（与 requirements Metadata 一致，F01–F18 全部为本期范围）。
- **端形态 / 响应式**：一套响应式网页（D-3）。
  - 断点：手机 < 768px，平板 768–1199px，电脑 ≥ 1200px。
  - 电脑端优先保证总览、矩阵、大表格；手机端优先保证待办、检查点核对与放行、看图、签认（NFR-001）。
- **工作台聚合**：登录后首屏是**跨工地的「我的待办」**。
  - 按角色汇总待签基线、待签图纸、待签变更单、待放行、待核对、待预算定价、待出图、被退回或驳回、超时、未放行先覆盖等事项（REQ-F16-01）。
  - 同屏列出「我的工地」卡片。点进工地后默认打开项目总览。

## 3 角色 & 权限
- **上游已确认的认证方式**：邀请制 + 手机号密码（D-10）。忘记密码由公司管理员重置，没有自助找回入口（不做短信），登录页只提示「请联系公司管理员重置」。
- **登录态**：7 天无操作失效；修改密码后其他设备下线（AC-F02-05、AC-F02-08）。
- **角色分层**：公司管理员（公司级）、业主 / 业主代理人 / 项目经理 / 设计经理 / 质检 / 预算专员（项目级，一人可兼多个角色）。权限矩阵见 PRD §2.1。
- **同页角色差异**：
  - 无权限的**操作按钮直接隐藏**，不置灰。
  - **无权限的数据区块整体不显示**，比如设计经理和质检看不到合同专区入口。
  - 只读角色看到的是同一页面的只读态（例如业主看工作项）。
  - 越权直接访问链接时，显示无权限页（AC-F01-05）。

## 5 通用交互范式
- **列表**：分页（每页 20 条，电脑端可选 50 条）；顶部是筛选和搜索；工作项表支持楼层 / 房间筛选（沿用原型 chips）。只有基线签认支持批量操作。导出走专门入口（Excel / CSV / 证据包）。
- **表单**：提交时校验，错误显示在字段旁并列出全部缺失项；必填项加红色星号。现场核对表单自动存本机草稿，弱网下照片上传失败可以重传，照片全部上传成功后才能提交（PRD §7.1）。离开未保存的表单时拦截确认。
- **反馈**：
  - **不可撤回的操作**（签认、放行、驳回、作废、标记已覆盖、标记已付）弹出「确认内容摘要」，二次确认后才提交。
  - 普通保存用顶部提示条。
  - 待办数量显示在导航红点上。
  - 催办用「复制微信消息」。

## 6 视觉风格锚点
- **明暗**：只做浅色，沿用原型（工地白天强光下更易读）。
- **风格**：沿用原型 v1.20 的信息密集 B 端风格：浅灰底 #f4f6f9、白卡片、蓝色品牌色 #1e5fd0；工段沿用原型色板（砌墙 #c2410c、水电 #0f766e、铺砖 #b45309、木工 #166534、油灰 #7c3aed、安装 #0369a1）。
- **Category**：B 端数据密集型工作台（Productivity / Dashboard）。
- **情绪**：可信、冷静、可追溯。
- **交互哲学**：色彩响应。状态用颜色和标签表达，不用阴影抬升或位移动画。
- **字体**：系统中文字体栈（PingFang SC / Microsoft YaHei），数字等宽对齐。
- **设计签名**：**印章式状态标签**，用描边加微倾斜的「章」样式标示「已签认 / 已放行（绿）」「不得覆盖 / 不一致（红）」「待放行 / 待重签（橙）」「代理放行（蓝）」，全站统一。

## 7 数据与集成
- **核心实体**：公司、用户、项目、项目成员角色、邀请、楼层、房间、工段、工作项、图纸分册、图纸版本、基线（及修订）、检查点、核对记录、照片、放行记录、覆盖事件、变更单、问题、经验条目（及版本）、出勤、验收图片、资料文件、档案分类、补充事项、留言、计划留档、付款节点、待办（派生）、关键记录摘要链、操作日志。
- **外部对接**：无第三方系统接口。文件接口包括 Excel / CSV 导入导出、原型 JSON 导入、证据包 ZIP 导出。
- **数据访问方式**：前端通过本系统后端 API 访问数据；不直连数据库。
- **同步策略**：实时读写；待办在打开页面和每 60 秒刷新一次。
- **方案前置能力**（照抄 requirements）：
  - 对象存储：committed，装修公司负责，首次上线部署前；不可用时用本地磁盘存储加每日备份。
  - 公有云服务器、域名与 ICP 备案：committed，装修公司负责，首次上线部署前；备案前用临时地址内测。
  - 这两项阻塞的需求：REQ-F04-01、REQ-F06-02、REQ-F12-01、REQ-F17-03、REQ-F02-01、REQ-F02-02。

## 8 技术栈 & 架构 & 部署
- **方向**：前后端分离的单体应用，单实例部署在国内公有云服务器（容器化），数据库用关系型数据库，文件放对象存储（系统级 deployment-secret 配置，不做配置页）。
- **国内可达**：所有依赖和前端资源自托管或使用国内可达镜像，不依赖海外 CDN 和托管。
- **具体框架与版本**：在技术方案中按官方发布来源核实后确定。

## 9 安全 & 运维
- **认证**：邀请制 + 手机号密码，加盐慢哈希（NFR-006）；输错锁定（AC-F02-06）；不做二次验证。
- **脱敏**：经验库自动脱敏（AC-F09-01）；合同专区按角色可见（AC-F12-06）；手机号在成员列表中显示为 138****1234（只有公司管理员可见完整号码）。
- **备份**：每日自动备份数据库并核对文件清单，保留 30 天（NFR-005）。
- **审计日志**：所有写操作留日志（AC-F17-06），关键记录摘要串联（AC-F17-02）。审计与证据包页面向业主和公司管理员开放。
- **操作可逆性**：关键记录不可改删，更正靠追加；资料、问题只能作废不能物理删除；留言删除后显示占位。
